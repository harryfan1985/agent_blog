Agent 骨干模型已知道该裁剪什么：SWE-Pruner Pro 从内部表征读取 39% token 节省

August 6, 2026

编码 Agent 的骨干模型已经知道该裁剪什么——线性探针 AUC 远超基线，39% token 节省零质量损失

多轮编码 agent 的 token 预算 70%+ 花在工具输出上（文件读取、命令执行），其中大量内容重复或不再被引用。现有裁剪方法要么不感知 agent 意图（通用压缩），要么需要外部评分模型和每轮手写查询（任务专用裁剪）。SWE-Pruner Pro 提出了一个更简洁的方案：直接从骨干模型的隐藏状态读取裁剪信号。

核心发现：信号已在内

作者收集了 ~2,260 条多轮工具响应（~155k 行），用 Claude Sonnet 4.6 逐行标注 keep/prune。然后冻结 Qwen3-Coder-Next，mean-pool 最后层隐藏状态，拟合逻辑回归。结果：AUC 远高于多数类基线（0.30 at ~30% positive rate）。LDA 判别轴上两个类别有明显不同均值——keep-or-prune 信号已存在于骨干模型的表征空间中。

方法：从 prefill 读取信号

流水线

每轮交互时，骨干模型对 [历史, 工具调用, 工具响应] 做 prefill，SWE-Pruner Pro 的 head 从这次 prefill 的隐藏状态读取行级裁剪信号。前缀已在 KV cache，仅转发工具响应的新 token——零额外前向传播。裁剪后的响应替换原始响应进入下一轮历史。

Head 架构（3 个组件）

组件设计理由
长度感知嵌入8 个 log-spaced 行数桶（0-2 到 >200），加法式，零初始化5 行响应误删几行是灾难，300 行同样误删可忽略——误删代价与长度非线性相关
逐 token 分类器LayerNorm → 2× Linear-GELU-Dropout → Linear非线性而非纯线性：解决线性探针的中间重叠 + 与长度嵌入交互
行级决策逐 token sigmoid 阈值 0.5 → 行内多数投票保留代码语法结构，允许细粒度裁剪

Per-Sample Balanced Focal Loss

LLM 标注的 keep-ratio 本身是信息量指标：3/100 行保留时那 3 行信号最强，90/100 保留时那 10 行裁剪信号最强。标准交叉熵只看到全局 keep-rate，过拟合典型 30%，稀释极端比例样本。Per-sample balancing 在每个样本内分别计算 keep 和 prune 的 loss，等权平均——每个样本的少数类被保护。

训练：22,609 样本，15 分钟/epoch

  • 数据：5 个 HuggingFace 数据集，6,252 条真实 agent 轨迹，Claude Sonnet 4.6 逐行标注
  • 冻结骨干：预提取隐藏状态缓存到磁盘，head 从缓存特征训练
  • 硬件：单 8×H200 节点，~15 分钟/epoch
  • 优化器：AdamW，lr=3e-5，cosine decay，focal γ=2

工程启示

1. Agent 的内部表征是免费信号源

骨干模型在 prefill 时已经处理了工具输出并形成了相关性判断。此前方法花费额外模型调用来恢复这个判断，而 SWE-Pruner Pro 直接读取——零额外前向。

2. 长度感知是关键

误删代价与响应长度非线性相关。8 个 log-spaced 桶让 head 学会"短响应保守、长响应激进"——消融显示加入长度嵌入后 judge score 提升，F1 不变（错误重分布到更长响应）。

3. Per-sample balancing 比全局 balancing 更优

keep-ratio 本身是信息量指标。全局 focal loss 过拟合典型 30% keep-rate；per-sample balancing 保护每个样本的少数类，使极端比例样本（信号最强）不被稀释。

局限与诚实标注

  • 仅开源模型：需访问骨干模型隐藏状态，闭源 API（GPT/Claude）不适用
  • Python 为主：训练语料 ~83% Python + CLI，非 Python 语言覆盖待验证（论文自认）
  • LLM 标注噪声：Claude Sonnet 4.6 标注是模糊的，per-sample balancing 部分缓解但未根除（论文自认）
  • API call 增加：裁剪改变历史，agent 条件于不同的后续上下文，API 调用数可能增加（Qwen3: 131.9→139.8）

一句话

编码 agent 骨干模型在被动读取观察时形成的表征，已经编码了此前方法需要额外模型调用才能恢复的相关性判断——与其围绕 agent 构建裁剪，不如读取 agent 已形成的信号。
