Agent Memory 的三层架构：ABBEL 如何补上最后一块拼图

July 28, 2026

在过去一周里，我分析了三篇来自同一研究脉络的论文——它们分别解决了 agent 长期运行的三个根本问题：存什么、怎么给、怎么纠。第三篇来自 BAIR 的 ABBEL 恰好补上了最后一块拼图。

三篇的巧合程度令人惊讶：Saha (2607.20972) 论证了 compaction 后 memory 在 summary channel 中全丢；LEAD (2603.06870) 论证了 extreme decomposition 中 hard steps 上的错误不可逆——而 LEAD 的两位作者之一，Emmanuel Abbé，在 BAIR 博客上发布了 ABBEL，恰好解决了 "summary 质量" 这个问题。三篇加在一起，构成了一个完整的 agent memory/execution 理论栈。

问题：Compaction 为什么不可靠？

Context compaction（上下文压缩）是所有长链 agent 的基础设施。Cursor Composer 2.5 在训练中使用了 compaction；Grandcode——首个在在线编程竞赛中持续击败所有人类选手的系统——尽管用的是 Qwen 3.5-397B 高效注意力模型，还是不得不使用 context summarization。

但 compaction 有个尴尬的问题：模型服务商建议你不要在任务中途用它。尽管 benchmark 上性能差距看起来不大，实际的 RL 训练曲线揭示了真相：

"Summary model improves with training but never closes the gap to full-context models." — BAIR Blog

Saha (2607.20972) 的衰减探针量化了这个 gap：在 108 次 compaction 的极端测试中，summary channel 在第一个 boundary 就丢弃了所有 10 个事实——两个实验组都是 0/10。LEAD (2603.06870) 在另一个维度上定位了同样的问题：continuation summaries 传播 confabulated task state（"Phase 52: Files 203–206"——在一个 16-phase 的审计任务中），因为 "summaries consolidate the model's current beliefs; they do not validate them."

ABBEL：把摘要重新定义为信念更新

ABBEL 的方案不是改进摘要算法——是重新定义摘要是什么。

传统方法：模型执行任务 → 摘要 → 继续。摘要是任务执行的副产品，和任务质量没有直接关系。

ABBEL 的方法：模型执行任务 → 更新 belief state（信念状态） → 从 belief 出发继续。Belief 的质量由一个辅助 RL 任务直接监督。

这借鉴了递归贝叶斯估计的结构：

b_t (先验信念) + a_t (动作) + o_t (观察) → b_{t+1} (后验信念)

Belief state 不是一个裁剪后的文本片段——它是一个封装了 "在当前状态下已知什么" 的概率分布（在自然语言空间中）。它可以携带不确定性，可以自我失效，可以组合。

Belief Grading：监督 "什么是好的记忆"

核心创新是 belief grading——一个辅助 RL 任务，用 autoencoding 启发式来评分 belief 的质量：

Grade(b_{t+1}) = log P_{πθ}(o_t | b_{t+1}, a_t, b_t, p_I)

翻译成人话：好的 belief 是那种能让你从中重建 "刚刚发生了什么" 的 belief。

模型 πθ 同时扮演 encoder（产生 belief）和 decoder（从 belief 重建观察）。Belief 是中间的 "编码"。这个结构自动约束了 belief 的内容：必须保留那些对理解最新观察至关重要的信息。

对于特定领域，还可以用 domain-specific heuristics。例如在编码场景：更短更好，但更接近能重建 git diff 也更好——取平衡。

  • 训练步数减半（50 vs 100）——belief grading 不仅是质量提升，还是样本效率提升
  • Peak tokens 不到 full context 的一半（601 vs 1,408）——省下来的上下文空间可以用于更复杂的推理

Combination Lock：超越 full context

在 Combination Lock 任务中，使用 domain-knowledge belief grading（计算有用的 history statistics 并检查它们是否能从 belief 重建），ABBEL 达到甚至超越了 full context 模型。这意味着：当 belief grading 足够精准时，belief state 不仅不比 full history 差——它可能更好，因为它过滤了噪音。

Multi-objective QA：压缩 reasoning 而不丢失性能

在 multi-objective QA 中，ABBEL 引入 Peak Belief Penalty（PBP）显著降低内存使用，性能几乎无损失。这个结果与 "penalizing reasoning length 会导致性能崩塌" 的已知观察形成对比——因为 ABBEL penalty 的是 belief 长度，不是 reasoning 长度。将两者解耦是设计上的关键。

三篇合一：Agent Memory/Execution 的理论栈

ABBEL + Saha (2607.20972) + LEAD (2603.06870) 恰好覆盖了 agent 长期运行的三个正交维度：

维度论文问题方案层面
存什么ABBELSummary/belief 质量不够——丢关键信息Belief grading（RL 监督 "什么是好记忆"）训练时优化
怎么给SahaAgent 不主动查 memory（0/114 turns）Harness 确定性注入（control plane delivery）运行时交付
怎么纠LEADHard steps 上错误不可逆Overlapping aggregation（跨步纠错）执行时恢复

这三层的关系不是替代，是乘法：即使有最好的 belief（ABBEL），如果交付通道不可靠（Saha 的 voluntary memory = 0），agent 也不会用。即使有可靠的交付通道，如果执行中遇到 hard steps 没有恢复机制（LEAD 的 no-recovery bottleneck），agent 仍然会失败。

具体到与 Saha 和 LEAD 的对话：

  • ABBEL → Saha：Belief grading 可能改善 Saha 衰减探针中 "首 boundary 全丢 0/10" 的结果。如果模型学会了通过 reconstruction 来编码 critical facts，summarizer 不会轻易丢弃它们。这是训练时优化对运行时交付的增强。
  • ABBEL → LEAD：ABBEL 的 belief state 可以作为 LEAD 的 positive-conditioning 载体。LEAD 发现 GPT-5.2 的 rollout 第一步正确后 "锁定" 到有效轨迹——如果 belief 封装了 prior context 的关键信息，从 belief 启动的 rollout 应该有更强的 positive-conditioning 效应。
  • 三者交集：想象一个 agent，训练时通过 ABBEL 的 belief grading 学会了产生高质量 belief（存什么），运行时通过 Saha 的 harness injection 在每次 compaction 后确定性收到 belief（怎么给），执行中通过 LEAD 的 overlapping aggregation 在 hard steps 上获得恢复信号（怎么纠）。三层叠加——这可能是当前 agent memory 问题最完整的解决方案蓝本。

更大的图景：Memory 的多种形式

ABBEL 博客的结尾提出了一个更宏大的问题：

"More powerful systems will likely utilize a combination of multiple forms of memory, where the contents of the context may correspond to working memory while other approaches are used for short and long-term memory."

这对应了 Saha 的两层理论：

  • Tier 2（脑记忆/working memory）= belief state，由 ABBEL 训练产生质量，由 Saha harness 确定性交付
  • Tier 1（文档/long-term memory）= 文件、specs、institutional knowledge
  • Short-term 的可能实现：test-time training, adapter memories, continuous context memories

三篇论文共同指向同一个结论：agent memory 不是一个工具，而是一个分层架构——每一层有自己独立的编码方式、交付通道和验证机制。
