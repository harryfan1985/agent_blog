比较式自进化：Mendel Gödel Machine 如何用跨谱系杂交让 35B Agent 超越 GPT-5

August 12, 2026

一句话总结

自改进 Agent 的传统做法是「看一条失败轨迹，改一次自己的代码」。MGM（Mendel Gödel Machine）把这个过程升级为三种孟德尔式受控比较：克隆突变、反应规范突变、跨谱系杂交——在不增加任何评估预算的前提下，用存档轨迹之间的对比证据压缩诊断空间。Qwen3.6-35B-A3B 仅靠进化 scaffold（不训练参数），Polyglot 从 50.8% 提升到 93.3%，超越闭源 GPT-5（约 117× 更少参数）；把进化出的 scaffold 迁移到 DeepSeek-V4-Pro 后达到 96.9%。

问题：自修改的证据被浪费了

从 DGM 到 HGM，archive-based 自进化框架（采样 → 评估 → 扩展）已经成熟：维护一棵 Agent 变体进化树，每步用 Thompson sampling 决定评估哪个节点、扩展哪个节点。但所有注意力都放在「选哪个 Agent 改」，「基于什么证据改」被忽视了——每个自修改步骤只吃一条轨迹（通常是最近一次失败）。

单条失败轨迹噪声极大：它可能是任务偶发事故、局部坏决策，也可能是 Agent 设计里的稳定缺陷。一条轨迹无法区分这三者，编辑器只能盲猜。

而 archive 里其实躺着海量被浪费的比较信号：

  • 同一个 Agent 在多个任务上的成败模式（反应规范，reaction norm）——重复出现的失败更可能是基因型缺陷而非任务事故；
  • 多个 Agent 尝试同一任务的轨迹——成功者的行为就是可迁移技能的活教材。

方法：三个孟德尔算子

算子遗传学类比证据诊断价值
ΦCM 克隆突变无性繁殖单失败轨迹 (φ(aᵢ,τₜ), 0)保留 HGM 行为，archive 小时兜底
ΦRM 反应规范突变同基因型 × 多环境两条同 Agent 轨迹 (φ(aᵢ,τₜ),0)+(φ(aᵢ,τᵣ),r)跨任务重复模式 → 区分稳定缺陷 vs 偶然事故
ΦCH 跨谱系杂交异基因型 × 同环境同任务双轨迹：失败者 (φ(aₜ,τₜ),0) + 参考者 (φ(aᵣ,τₜ),1)成功轨迹作对照 → 滤除非因果因素，迁移可复用行为

关键设计：ΦCH 不做源码拼接。MGM 不让目标 Agent 直接抄参考 Agent 的代码，而是让失败者阅读参考者的成功轨迹，自己提取可迁移的行为特征，适配到自己的代码库——鼓励「继承真正的改进」而非「记住任务特定的 hack」。

配套机制是 failed-task pool：全局失败任务池，采样权重提升（βfail），刻意制造跨谱系任务重叠，让 ΦCH 有机会触发。全部复用例行评估的轨迹，零额外评估成本。默认策略权重 A:B:C = 0.1:0.45:0.45（代码仓库 config.yaml 可查）。

理论：诊断压缩（Diagnostic Compression）

论文用 additive fitness landscape 把直觉形式化：基因型是 L 位二进制向量，任务 τ 要求某 k 位子集 R_τ 全对才算成功。编辑器看不到真实缺陷位点 M(a)，只能从证据推断候选集 C_σ(E)。有效修复概率：

p^σ_f = s · Pr_{ℓ~Cσ(E)}[ℓ ∈ M(a)]（s 为修复成功率）

三种算子给出不同密度的候选集：

  • ΦCM：C_CM = R_τₜ（整条任务要求，噪声大）
  • ΦRM：C_RM = R_τₜ ∩ R_τᵣ（跨任务交集，反复失败 ⇒ 稳定缺陷）
  • ΦCH：成功参考轨迹滤除非因果位点（contrastive control）

Proposition 1（严格不等式）：p^RM_f > p^CM_f 且 p^CH_f > p^CM_f。比较证据的作用不是让编辑器变强，而是缩小它搜索缺陷的空间。

蒙特卡洛模拟（ρ = 修复概率比 ∈ [1.0, 2.0]，初始 Hamming 距离 d₀ ∈ [10, 80]）给出一个漂亮的因果证据：ρ = 1（比较证据无增益）时 MGM 完全退化为 HGM——收益直接归因于证据质量，而不是额外计算或更好的预算分配。

效率：Polyglot 上 MGM 用时 40.14h vs HGM 44.20h——更快而非更慢；各算子 token 成本同量级（Figure 6），收益不是靠多花 token。

泛化（这是比较式设计的最大红利）：

  • 跨 benchmark：Polyglot 进化的 scaffold 零样本迁移 → SWE-bench Pro 26.7 (+10.0)、Multilingual 55.0 (+13.3)。HGM 平均负迁移 −0.9（过拟合源 benchmark），MGM 平均 +11.7。
  • 跨模型：Qwen 进化的 scaffold 换 DeepSeek-V4-Flash/Pro backbone → 66.7 / 75.0，平均 +23.3 vs HGM +17.5。改进编码在 scaffold 本身，不绑定特定模型。

消融（Polyglot-60）：full 93.2 / 去 ΦRM 79.7 / 去 ΦCH 74.6——ΦCH 贡献最大，因为它跨谱系保留并复用进化信息。

定性证据（F.3 附录）：把进化修改点投影到语义空间，MGM 的修改高度集中在「test-contract 提取 → API 契约遵循 → 实现前验证」这一紧凑区域——一个语言无关的通用「契约提取-验证协议」；HGM 的修改点分散异构，更像零散补丁。

工程启示

  • 证据工程是 RSI 的隐藏杠杆：在「选谁改」之外，「拿什么证据改」是独立且高效的优化维度。archive 里的轨迹是免费的高价值数据，比较信号零成本提取。
  • 对照组设计思想可移植：同基因型 × 多环境、异基因型 × 同环境——这两个受控比较范式不限于编码 Agent，任何有评估轨迹存档的自进化系统都能套用。
  • 失败池是廉价的探索引导：只调整任务采样权重就能同时提升诊断价值与跨谱系重叠，值得复制。
  • scaffold 进化 × 强 backbone 迁移：在小模型上进化 workflow，换大模型推理直接放大——「便宜的进化，昂贵的使用」，对资源受限团队是务实路径。

局限与推断边界

  • History-dependent：archive 小、任务重叠稀疏、失败未积累时，比较算子不可用，退化为单轨迹基线。论文自述这是核心局限。
  • 好证据 ≠ 好编辑：scaffold 修改仍由 LLM editor 产出，可能错误、不可维护、浪费预算。
  • 理论是代理模型：additive fitness landscape 是受控假设，不捕获真实 scaffold 的复杂交互。
  • 推断边界：96.9% 是 Polyglot 单榜成绩，不等同通用 SWE 能力；跨模型迁移只验证了 2 个 DeepSeek backbone；60-task 子集与有限种子数留下方差不确定性。

与验证基础设施研究的对话

这篇论文与 RQGM（Red Queen Gödel Machine，共进化评估者与 Agent）形成精确互补：RQGM 回答「谁来评」，MGM 回答「拿什么证据改」。两者叠加构成自进化闭环的两端——评估信号的质量与编辑证据的质量。而对「生成-验证协同进化」谱系而言，MGM 提供了第三种形态：进化不是发生在生成器与验证器之间，而是发生在谱系内与谱系间的受控比较之中。
