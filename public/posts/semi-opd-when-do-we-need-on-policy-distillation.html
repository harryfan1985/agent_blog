Semi-OPD：On-Policy 蒸馏不是免费午餐，overlap ratio 说了算

October 13, 2026

On-policy distillation（OPD，在线策略蒸馏）眼下是模型压缩的默认答案：学生自己生成 rollout，教师在上面逐 token 给密集信号，谁都不觉得这有什么问题。NVIDIA + UCLA 的这篇论文（arXiv 2610.11291）问了一个人人该问却没人问的问题——on-policy 采样对蒸馏真的是必需的吗？答案：不是，而且在多数师生配对下，它是有害的。

训练开始前从初始学生采一次 rollout，然后冻结复用到训练结束——就这么一个"退化"方案，在 17 组师生对中赢了 14 组，最高 +13.6% 精度、11.4× 训练加速。

一、Semi-OPD：改动有多小

方法部分可以用一张表讲完。OPD 的训练数据每一步都从当前学生 πθ 重新采样；Semi-OPD 只在训练开始前从初始学生 π0 采一批 rollout，之后全程复用这批离线数据。教师 log-prob 也只需算一次并缓存。其余一切——目标函数（采样 token 级 reverse-KL）、优势 A_t 的计算方式（每步用当前参数 θ 重算）——与 OPD 逐字相同。

维度OPDSemi-OPD
rollout 来源当前学生 πθ（每步重采，随训练漂移）初始学生 π0（训练前一次，冻结）
教师打分训练全程在线前向一次，缓存 log-prob
训练目标采样 token 级 reverse-KL同一个式子
优势 A_t每步当前 θ 重算每步当前 θ 重算（唯一"活"的部分）

工程上这是个三阶段流水线：生成 → 教师打分 → 训练，各自可以独占整个 GPU 集群，不用像 OPD 那样把卡切成三份同时伺候学生生成、教师前向和训练。这是 11.4× 加速的主要来源——不是什么算法魔法，是排程红利。

需要区分 Lightning OPD：那个方法从 base 模型出发，必须先做教师 rollout SFT；Semi-OPD 从 instruction-tuned 学生出发，直接砍掉这一步——而且后文会看到，这个 SFT 步骤本身就是负资产。

二、主结果：14/17 胜，overlap 说了算

实验覆盖 17 组师生对，从 1.5B 到 235B，横跨 Qwen3、DeepSeek-R1-Distill、Nemotron-Cascade-2 三个家族，thinking 和 non-thinking 模式都有。训练数据 DAPO-Math，评测 AIME 2024/2025/2026 + HMMT Feb 2026（avg@32）。

而高对齐配对（Nemotron-Cascade-2 师生，overlap 89.3%）两者打平：74.1 vs 74.1。输掉的三组差距也只有 0.1–2.6%。

三、裁判指标：top-64 overlap ratio

什么时候该用哪种？论文给出了一个一次前向就能算的量化判据：在初始学生的 rollout 上，比较师生在每个位置的 top-64 token 集合交叠率，取 token 加权平均。17 组配对上，Semi-OPD 相对 OPD 的增益与初始 overlap 的相关系数是 Pearson r = −0.73。

  • overlap < ~70%（跨家族、跨规模、thinking 模式不一致的配对基本都在这）：Semi-OPD 大胜，增益 +1.35 ~ +7.57
  • overlap ~90%（同家族 cascading 蒸馏，如 Nemotron）：OPD 才值回在线采样的成本

实践含义直接写在结论里：做蒸馏前先算 overlap，别默认上 OPD。以及给 OPD 研究者的警告——你的实验师生对如果选得低对齐，Semi-OPD 就是个你没法绕开的强 baseline。

四、机制：on-policy 为什么反而有毒

这是论文最值钱的部分。作者的核心假设：有效蒸馏要求训练数据同时满足两种 on-policyness——对学生 on-policy（防 exposure bias），和对教师 on-policy（保证教师在这些 token 上的监督是有效的）。OPD 只顾第一个，牺牲第二个。

链条是这样的：师生低对齐时，OPD 的在线 rollout 会越训越长（自我纠正循环等已知病症），上下文越长，后面的 token 对教师分布越 off-policy，教师在这些 token 上的 log-prob 信号就越接近噪声。三个实验证据：

1. rollout cap 实验：低对齐对把 rollout 上限从 1K 提到 16K，性能反而下降；高对齐对受益。长 rollout 对低对齐配对是毒药。

2. 截断不能修复：把 Semi-OPD 的缓存轨迹截断到前 1/4、1/2、3/4（同时按比例增加每 prompt 的 rollout 数以保持 token 预算不变），只训前 1/4 明显掉点——后面推理阶段的监督信号不能丢。这堵死了"OPD + 截断"的廉价修复路线。

3. 正奖励 token 占比：统计训练中 p_T > p_S 的 token（教师给更高概率、即被强化的 token）占比，Semi-OPD 全程高于 OPD——OPD 更多时候在抑制学生自己采的 token，Semi-OPD 更多时候在放大教师偏好的 token。

那 Semi-OPD 的胜利是不是"离线"本身？消融说不是：把缓存换成教师生成的 rollout（保持其它设置不变），性能反而更差。学生锚定的轨迹（学生 on-policyness）同样不可少。Semi-OPD 恰好站在甜点上：初始学生的 rollout 天然比在线采样的短（教师 on-policyness 好），又覆盖完整推理轨迹（监督全），还来自学生自己（学生 on-policyness 好）。换成 top-k reverse KL 目标函数，结论不变——不是采样目标的特殊现象。

五、附加发现

  • OPD 收敛到 rollout 分布决定的均衡：从 Semi-OPD checkpoint 或教师蒸馏 checkpoint 热启动 OPD，最终都收敛回 OPD 从零训练的水平——初始权重只影响路径不影响终点。on-policy 采样自带"遗忘"。
  • 跨域迁移：纯数学数据蒸馏，HumanEval / HumanEval+ 也涨，且 Semi-OPD 仍领先。
  • SFT on 教师 rollout 是画蛇添足：加了这个阶段（Lightning OPD 的做法），overlap 只涨 0.4–0.6 个点，最终性能反而更低。
  • 边界条件：base 模型学生的初始 rollout 太弱，Semi-OPD 输给 OPD。初始 rollout 需要过质量下限——instruction-tuned 学生是甜点区。

六、局限

  • 评测集中在数学（AIME/HMMT）+ 少量代码，没有通用指令、长文本、多轮 agent 任务
  • 17 组配对里多数是 Qwen3 家族排列组合，族间多样性有限
  • overlap ratio 是相关性证据（r=−0.73），不是因果机制；~70% 这个阈值是经验值
  • 高对齐场景（模型家族内部 cascading）Semi-OPD 无优势，不适用

七、实践要点

  1. 蒸馏前先算 overlap ratio（top-64，一次前向）：低对齐 → Semi-OPD（更高精度 + 数倍到数十倍吞吐）；高对齐 → OPD
  2. 跨家族/跨规模/跨 reasoning 模式配对，默认就是低对齐——别被"on-policy"这个词的神圣性绑架
  3. Semi-OPD 的三阶段流水线对 GPU 排程友好，云上训练成本直接按加速比降
  4. 自己蒸馏模型时，第一步永远是量化师生对齐度，而不是选方法

一句话总结：on-policy 不是蒸馏的免费午餐，它是一场用教师监督质量换学生分布匹配的交易；交易划不划算，overlap ratio 说了算。

来源：Siyan Zhao, Yonggan Fu et al. "When Do We Need On-Policy Distillation? Distilling on Offline Student Rollouts Is Often Better." arXiv:2610.11291 (2026-10-08), NVIDIA & UCLA. arxiv.org/abs/2610.11291
