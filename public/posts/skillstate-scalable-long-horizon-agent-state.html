SKILL.state：别管理 Agent 的对话历史，直接删掉它

September 1, 2026

问题：长程 Agent 的执行，正在被对话历史拖垮

LLM 智能体越来越常被派去执行几百步的长程过程性任务：软件工程、工作流自动化、web 交互、科学发现。但主流运行时几乎全是「对话式执行」——每一轮把全部历史（推理、动作、观察、工具输出）重新喂给模型。后果随执行步数线性恶化：提示词膨胀导致 O(T²) 级累计 token 消耗、「lost in the middle」式的注意力稀释、以及过期信息对当前决策的持续污染。

记忆系统（MemGPT、摘要式总结、检索式召回）只是把历史压缩，没有改变执行语义：决策仍然依赖对过去的文本重建，而不是对当前世界的显式表示。摘要本身也在积累——论文里 Memory 基线在 200 步时反而比纯 ReAct 更贵（617 万 vs 261 万 token）。

8 月 26 日登上 arXiv、被 EMNLP 接收的 SKILL.state 给出一个更彻底的答案：不要管理历史，删除历史。把执行建模为显式状态迁移——模型每一步只看到「技能说明 + 当前结构化状态 + 最新一条观察」，推理痕迹在状态通过校验后立即永久丢弃。

一、核心机制：状态是充分统计量

每一步的输入只有三样：Aₜ = (P, Σₜ, Oₜ)，即不可变技能说明 P、结构化执行状态 Σₜ（JSON schema，按领域编写一次、跨任务复用）、最新环境观察 Oₜ。

  • 模型输出：推理痕迹 Rₜ + 状态补丁 ΔΣₜ + 动作 aₜ。补丁经运行时确定性校验后合并进状态（null 值表示删除键），非法补丁触发回滚-重试，模型永远无法污染持久状态。
  • 推理即用即弃：步内 CoT 完整保留用于演绎规划，但状态迁移一经应用，Rₜ 永久丢弃，绝不进入后续提示词。
  • 复杂度：单步提示词 O(1)（与已执行步数无关），累计 token 从对话式的 O(T²) 降到 O(T)。

和既有方案的差别很关键：ReAct 是纯转录累积；LangGraph 虽然注入结构化状态块，但仍保留完整对话转录——只有 SKILL.state 把转录本身删掉，把结构化状态当作唯一的执行底座。

一个工程细节：InterCode CTF 全部 100 个挑战复用同一个 5 字段 schema（discovered_flags、tested_hypotheses、active_files、working_dir、cmd_summary）。schema 成本是一次性的。

2.2 噪声鲁棒性（T=50，注入 5/20/50 条干扰遥测/轮）

ReAct 从 0.68 崩到 0.53；SKILL.state 在所有噪声水平保持 ≥0.97。原因很直接：干扰在状态补丁生成时就被过滤掉，永远不会进入下一轮的提示词。

2.3 状态恢复（外部悄悄改写世界）

物品被外部挪走、分支被 force push——历史型基线会幻觉 5–14 轮（过时事实压制新观察），SKILL.state 0 步恢复：决策基于当前结构化状态，纠正警报一到立即更新。

三、最关键的消融：预算匹配对照

"是不是只是提示词短？"论文把 ReAct 系基线全部限到与 SKILL.state 相同的 ~1,800 token 预算（T=100）：

配置分数
完整 ReAct（不设限）0.84
Truncated 滑动窗口0.18
Summary-capped0.52
ReAct + LLMLingua 压缩0.22
SKILL.state（结构化）0.94

滑动窗口把早期关键分配踢出上下文直接崩盘；LLMLingua 的统计熵过滤删掉了「看似冗余实则关键」的槽位 ID。结论：收益来自结构化状态对精确关系依赖的保存，统计压缩会毁掉它。

四、局限：充分统计量假设何时失效

论文的前提是「执行状态可以成为未来决策的充分统计量」。它会在三种场景下破碎：

  • 没有预先可知的固定 schema，状态结构需要执行中动态发现；
  • 某个早期观察的相关性当时未被识别、从未被写入状态——事后无法补救；
  • 任务目标本身定义在历史轨迹上（审计、调试溯源、解释过往行为），历史是产物而非开销。

另外：当前实现只覆盖单智能体，多智能体并发写需要确定性的冲突消解语义（⊕ 算子），论文未展开；小模型的结构化输出遵从是最大短板——Gemma-4-31B 的错误里 68% 是误删/覆盖状态键、20% 是 schema 类型错误、12% 是 JSON 语法，方向是约束解码（grammar-constrained decoding）。

五、对 Agent 工程化的启示

  • 任何跑长循环的 agent 系统都该做一次减法：每步只喂「技能说明 + 显式状态 + 最新观察」，把历史排除在提示词之外——这是立即可用的模式，不需要新模型。
  • 与长期记忆互补而非竞争：Mem0/MemGPT 这层管跨会话知识，SKILL.state 管单次执行内的状态。论文也引用了 Mem0 作为相关工作。
  • 反直觉发现：摘要式记忆在超长程任务里可能比不用记忆更糟（617 万 vs 261 万 token），「压缩」不是免费的。
  • 工程要点：schema 按领域写一次、校验器放运行时（不信任模型输出）、用 null 删除语义做状态减法。

这是长程 Agent 从「聊出来的」走向「跑出来的」的关键一步：执行系统的职责不是记住对话，而是维护一个可信的当前世界。
