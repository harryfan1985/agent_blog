下一代模型会淘汰你的技术吗？35 篇 ICSE 论文的半衰期实测

September 2, 2026

ICSE 是软件工程领域的顶会。2026 年的 ICSE 里，45% 的论文摘要都提到 LLM——研究者们热火朝天地构建多 Agent 工作流、迭代细化管线、专用工具链。UVA less-lab 的研究者们问了一个所有人都在回避的问题：这些投入，值得吗？

核心发现：37%–63% 的 ICSE 2026 LLM 技术（发表不到半年），已经被「新模型 + 一条自动生成的 prompt」原生超越。技术半衰期不足一年。

一、引子：AutoVerus 的两个月

2025 年 10 月，AutoVerus 发布，成为 LLM 验证 Rust 代码的 SOTA——一整套精心设计的定制 Agent，把人类验证专家的知识、策略和迭代反馈回路全部工程化。两个月后，一个新基准发布：AutoVerus 解决了 20% 的问题，而 Sonnet 4.5 用一条简单的 prompt 原生解决了 81%。一代模型的更新，直接作废了整套工程复杂度，性能还是 4 倍。

这是 Richard Sutton「Bitter Lesson」的 SE 版：为修补 AI 暂时缺陷而设计的人类工程，会被规模化清算。

二、方法：最笨的基线

论文的做法刻意克制。基线是绝对最小的 LLM 使用方式：

  • Prompt 自动生成：由 meta-prompt 从论文文本直接生成，不手工调优
  • 单次调用：无迭代、无工具、无执行循环
  • 新模型跑分：Claude Sonnet 4.6——刻意选 trailing-edge 而非前沿模型，作为能力下限

他们从 ICSE 2026 筛出 47 篇可复现的 LLM 技术论文，随机分析 35 篇，为每一篇复刻原论文的评测协议（包括起 SWE-bench 的 Docker、同时拉起 PostgreSQL 和 MySQL 跑 SQL 翻译对比这种重活），每篇论文预算 15 美元。

三、结果：重工程 vs 单 Prompt

结果篇数
单 prompt 完胜原文技术13（37%）
混合（部分数据集/指标胜出）9（26%）
不敌原文13（37%）

几个代表性数字：

  • MultiPL-E Java Pass@1：单 prompt 78.85 vs 原文 61.9
  • Defects4J 测试通过率：98.9 vs 62.91（覆盖率也全面领先）
  • HumanEval 上，单 prompt 赢了所有遇到的技术

惨败的一面同样重要：日志分析 F1 18.5 vs 97.5；SQL 方言翻译 60.61 vs 97.98；漏洞检测单 prompt 误报 176 个（原文 0 个）。需要深度语义理解的任务，单 prompt 还差得远。

四、什么被替代，什么活下来

类别单prompt胜负混合
代码生成621
程序修复312
Bug 发现173
影响分析020

按策略看更清晰：

  • Search and Selection（生成 N 个候选再筛选）：3/3 全部被替代——新一代模型已经原生会了
  • Structured Reasoning（拆解推理步骤）：5/9 被替代——模型能内化
  • Domain-Specific Processing：4/5 不敌；Knowledge Grounding：4/8 不敌——领域知识和项目级上下文注入，单 prompt 学不来

幸存者的共同特征：给模型提供它自己无法生成的额外信息——静态分析结果、方法依赖、领域规则。这些与模型能力同向缩放，会被放大而非抹平。

五、白盒 Prompt 不值

论文还测试了把原论文方法论嵌入 prompt 的「白盒」版本。结果：白盒赢 14 篇，黑盒（不含方法论）赢 12 篇——无一致优势。白盒平均多花 80% token，贵 15%。

原因：当模型无法调用论文里用到的工具（静态分析、fuzzer）时，方法描述只是干扰项。有趣的例外是 Feedback and Validation 类技术——描述验证标准似乎能帮模型预判输出会被如何评价，促使它内部先自我修正。

六、对我们的启示

  1. 别为模型的临时缺陷造复杂脚手架。这条对个人 Agent 工作流同样成立：你为一个模型垫的 workaround（复杂 prompt 链、多层重试逻辑），换下一代模型后大概率是负资产。
  2. 先试最笨的方案。新模型 + 一条结构化 prompt，跑不过再上工程。工程复杂度必须证明自己。
  3. 值得投入的方向：领域专用处理、项目级知识注入、给模型喂更丰富的结构化上下文——这些会随模型变强被放大。反过来，如果你的 pipeline 核心价值是「生成候选再排序筛选」，新模型已经原生会了。
  4. 审稿新姿势：读 LLM 技术论文时，先问「这个工程复杂度 vs 单 prompt 基线的增量是多少」。

论文自己也指出了边界：单 prompt 禁用工具是设计使然。加一个基本执行循环或工具访问，可能就能追平剩余差距——这正是 Agentic 实现的空间，但前提是它能证明自己跑赢基线。
