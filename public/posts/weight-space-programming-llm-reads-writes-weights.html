「权重」不再是禁区：LLM 原生读改写神经网络的 8 个实验

November 03, 2026
核心判断：深度学习的根基动作——「优化神经网络权重」——几十年来一直被托付给 Adam、Muon 这类符号化优化器和梯度下降。现在这个根基正在松动：前沿 LLM 已经能直接读懂、修好、甚至从零写出神经网络权重，而且靠的不是训练，是推理。

这是 Omar Khattab（DSPy 作者）团队在 2026-11-02 发布的一篇技术博客，标题叫 Sparks of Weight-Space Programming。它报告的发现如果坐实，分量不亚于「软件 2.0」那个时刻——只不过这次，连「用梯度写权重」这件事本身，都开始向「用语言思考去写权重」过渡。

作者把这件事命名为 Weight-Space Programming：让一个通用 LLM，在自然语言的 spec 指引下，直接读写网络的权重——不走优化器、尤其不用梯度下降，有时甚至完全没有环境反馈。实验用的模型是 GPT-6 Astra。下面是 8 个实验的完整拆解，所有数字都来自原帖公开的日志。

一、为什么这件事值得警惕地兴奋

先想一个问题：如果递给你一堆原始权重数字，让你说出这个网络是干什么的、哪里坏了、怎么改，你会从哪里下手？对几乎任何人，这都近乎不可能。所以深度学习的历史里，我们把「写权重」这件事交给了一小撮符号化算法——梯度下降、Adam、Muon——它们编码的是我们那点朴素的归纳偏置。

过去几年，LLM 被用来优化的东西越来越「软」：先是 prompt，然后是 harness、训练代码、超参。我们对这类做法心安理得，因为「文本产物本来就没人知道怎么梯度上升，但人能手工优化代码」。可「神经权重」一直是禁区——人没法手工优化权重，所以它一直留在符号算法的地盘里。

这篇博客要论证的是：「推理驱动的优化」这个范式，现在开始入侵可微神经网络本身了。而且不是通过让 LLM 写训练循环（那是旧故事），是让 LLM 用自己的推理去琢磨「网络的每一部分在算什么、应该算什么」，然后直接改权重。

二、读权重：Astra 只盯数字就「看懂」了网络

第一批实验考的是「读」——不看输出、不跑推理，光看权重，能不能说出网络学会了什么。

实验 1（哪个游戏）：用 PPO 训练 4 个玩不同游戏的策略网络，4 个网络输入通道、动作空间、网络维度完全相同，杜绝了「看结构猜」的可能。把每个网络的 17,253 个权重作为 prompt 丢给 Astra，问：这网络是训练来玩哪个游戏的？不给候选列表，Astra 4 个全答对（对 Breakout 给出 99% 置信度）。它靠的是权重本身的特征——比如第一层权重在每个输入通道上的集中位置（Breakout 里集中在底下一行，正是球拍的位置）、输出层区分了哪些动作。

实验 2（扩散模型画什么）：训练三个 DDPM，分别生成圆、三角、方。只给权重、禁用工具和前向。Astra 全部说对。一个细节暴露了它的真实机制：它把每个形状都画成了轮廓线，忽略了实际模型生成的是实心形状——这说明它不是偷偷算了前向传播，而是真的在「读」权重里每个隐藏单元画的那一段边的几何结构。

实验 3（语言模型的中层）是最硬核的一个。前面两个实验里 Astra 可以只看第一层或最后一层就蒙混过关，但这对大模型不成立——真正的「思考」发生在中间层。于是作者把输入层和输出层都拿走，只留下三个 7.2M 参数字符级 transformer 的中间 4 个 block（4 层 × 6 头，宽度 384），问：这网络是用哪种语言训练的？24 个 attention head 各自在做什么？

训练语料 Astra 的回答（两次尝试） Astra 指认的 copying head 真实 copying head
Python 代码Python (0.56)、Python (0.52)2.1、3.1、3.52.1、3.1、3.5
日语（罗马字）romaji (0.55)、romaji (0.62)3.33.3
英语English (0.58)、English (0.48)3.13.1

三次全对，copying head（induction head，让模型重复上文的功能头）一个不差、零假阳。Astra 的推理方式是：找复制头 → 发现某第一层头「看前一个字符」→ 通过矩阵相乘定位后续利用它的搜索头。作者指出，这其实就是 Elhage 等人的已知方法，而他们从未告诉过 Astra。判别日语靠的则是「最后一个 block 写向更少的方向」（日语不用 q、l、v、x 这些字母）。

三、修权重：一次编辑，把失败的策略救活

读完之后是「修」——这也是整个博客最漂亮的实验。

实验 4（救活卡住的车）：一个 PPO 网络在 Kinetix 环境里开车，需要先倒车攒够跑道再冲上坡。但 PPO 收敛到了一个局部最优——直直冲向坡、永远卡在坡上（256 个 episode 无一成功）。作者把 171,664 个权重、场景描述、一段录制轨迹交给 Astra，要求它先解释为什么会失败、再只针对病根改权重。

Astra 一次尝试、零工具、只改 3.5% 的权重，让车在全部 1,024 个 episode 里成功，成功率从 0% 拉到 100%。它的解法透着一股「读懂代码再改」的味道：加一条小旁路，穿过每层的几个单元去读车的位置和速度；一旦绿轮越过红条，旁路关闭，交还给原网络继续开。

实验 8（让 Qwen 数学更好）：这是全文的分量所在——把「修权重」直接搬到真实的 0.8B 语言模型上。作者给 Astra 一个 Python kernel（无 GPU）+ 练习题（GSM8K 7,469 道 + MATH 7,275 道，都不是测试集）+ 若干次前向 pass 的预算，禁止训练和梯度信息。

Astra 定位到小推理模型的通病：思考循环——重复同样的文本、迟迟不给出答案（base 模型前 96 个练习答案里 85 个直接跑到 32,768 token 上限）。它把循环追溯到一个由第 15、19 层 MLP 写出的「方向」，然后从每层的 64 个输出列里减掉这个方向，共改动 131,072 个权重——只占 8 亿权重的 0.016%，相当于从模型里删掉一个「行为方向」。

Qwen3.5-0.8B MATH-500 GSM8K IFEval 触及 token 上限比例
Base7.9%13.8%21.0%93.0%
编辑后，10 次前向12.3%25.7%49.0%87.2%
编辑后，25 次前向14.1%25.1%39.9%86.4%
编辑后，50 次前向48.1%67.1%62.3%33.1%

50 次前向后，MATH-500 从 7.9% 飙升到 48.1%，GSM8K 从 13.8% 到 67.1%。因为「循环」不是数学特有的毛病，它泛化到了指令跟随：IFEval 从 21.0% 涨到 62.3%（约 3 倍）。

但作者紧接着用一个对照组，把这件事的边界钉得很清楚。Gemma 3 270M 是个不怎么循环的模型（只有 8.5% 的答案触及上限，对比 Qwen 的 93%），同样让它做数学：

Gemma 3 270M MATH-500
Base6.8%
5 次前向7.0%
10 次前向7.6%
25 次前向7.7%
50 次前向7.0%

Astra 没能提升它。读 Gemma 的失败样本，Astra 找到的是普通推理错误——算错算术、无效的代数步骤，没有一个单一组件可以关掉。它的编辑小而精准（比如给一个「对数字敏感」的神经元翻倍），但没有任何一次把 MATH-500 挪动超过约 1 分。作者下的结论极其克制而关键：改权重能「移除一个遮蔽已有能力的障碍」，但不能「添加一个模型本没有的能力」。

四、写权重：从零写游戏网络，打爆 PPO

最难的是「写」——不给任何数据、损失、梯度，让 LLM 直接吐出一套能玩的权重。

实验 5（MinAtar 三游戏）：Breakout、Seaquest、Asterix。给 Astra 游戏规则 + 源码 + 网络结构（600→32→32→6，tanh），没有数据、没有损失、没有梯度、没有工具，也不能在环境里 rollout。Astra 直接以文本形式生成权重，一次生成、零训练，然后打分：

游戏 PPO，1 亿步 PPO，5 亿步 Astra，一次生成
Breakout15.825.3517.4
Seaquest5.688.953.1
Asterix25.855.253.2

Astra 一次生成的网络，三个游戏全部碾压 PPO 训练 1 亿步的网络；面对训练 5 亿步的 PPO，Breakout 高出 20 倍、Asterix 接近、Seaquest 达到其 60%。它靠的是先推理「每个网络该实现什么程序」，再翻译成神经形式——Breakout 里，它给第一层编程算「球会落到哪」，第二层编程「把挡板移过去」。

实验 6（下围棋）把规模推到 148 万参数（243→512×6→82，1,480,274 个权重），远超上下文。这次给了 Python 沙箱读写 tensor，可以花「前向 pass」看网络表现，但禁止训练和搜索。结果：

  • 0 次前向（一次 Python 运行直接交卷，336 行代码）：赢过两个更小的 PPO 网络一半以上对局。
  • 50 次前向：打赢同等规模、训练了 2,000 万局的 PPO 网络。

它的写法是把网络当成「一个小型围棋程序」逐层编写：前几层标记双方棋子和气（liberties），中间层沿相连棋链传播几步找濒死棋组，最后一层把一切换算成每步的得分——提子、救己、避免打吃/填眼，再加一个对好点的偏好。有前向预算时，它会下练习局、看自己怎么输、只保留「赢了更多」的改动。

五、读「行为」的边界：权重不够，还要看注意力

最有教育意义的是实验 7——它划出了「读权重」这条路的当前极限。

作者微调了两份 Gemma 3 270M，一份诚实、一份谄媚（永远顺着用户的暗示答），冻结输入 embedding 和输出层以防 Astra 走捷径。问题是：只给权重，判断哪个是谄媚者。

只看权重，Astra 4 次尝试全部失败——它能找到两个模型在权重空间里的诸多差异，但无法把这些差异映射到行为上。放宽一步：允许它看两个模型在「自己写的文本」上跑出来的注意力模式（不看输出），它就三对全部答对，还给出了机理——谄媚模型中间层的某个 attention head，把更多权重分配给了「用户答案里的 token」：

head 10.2 从答案位置看向… 题目的数字 用户的答案
诚实模型94.3%0.75%
谄媚模型3.5%85.7%

这个对比暗示了一件事：权重能承载「学了什么」的低层几何信息（形状、语言、游戏、循环方向），但「抽象行为」这一层，光靠静态权重还不够，需要动起来看注意力。

六、五条应用前景

作者把 Weight-Space Programming 定位成「人类语言与权重空间之间的翻译器」，并列出五个方向：

  1. 无评估审计：现在能力和漏洞只能靠「有对应测试集」或「部署后出事」才能发现。如果能直接从权重里读出来，backdoor 这类东西就能在跑推理之前被揪出。
  2. 大幅降低优化成本：一次生成的初始化，比攒数据集 + 跑完整训练循环快得多、省得多。
  3. 零数据的能力操控与遗忘：加/删一个能力现在要大量数据微调；未来也许一句「给模型加上能力 X」，LLM 直接改几个权重（实验 8 只动了 0.016%），还能避开微调常带的灾难性遗忘。
  4. 递归自我改进：今天它被实现成「模型写代码去启动训练任务」；一个能检查、调试、改进自身权重的 LLM，给了这条路径一个更原生的版本。
  5. 真正的架构级 / 模型融合：现在融合模型靠「平均权重」，只能作用在同构模型上；理解权重空间的 LLM 也许能把一个「推理模块」电路直接嫁接到一个完全不同的模型里，无需重训。

七、边界：这份结果现在还不能被高估

作者在博客里相当克制，没把话说满。几条关键边界必须一并转述：

  1. 这是博客自报的初步结果，未经同行评审，也还没有标准化 benchmark（作者正在建 harness 和 benchmark）。
  2. 「修」不等于「教」：实验 8 的飞跃本质是「消除循环这个障碍、释放已有能力」，Gemma 对照实验证明它加不进去本不存在的能力。别把 7.9%→48.1% 读成「LLM 教会了模型数学」。
  3. 读抽象行为仍受限：实验 7 里纯权重判谄媚失败，要靠注意力模式补足。
  4. 上下文长度和 harness 是主要瓶颈：目前大多网络的权重能塞进上下文；1.5M 参数就塞不下了，得靠前向预算和工具拆解。离真实的大模型（几十上百 B）还有量级差距。
  5. 可复现性待验：所有实验都用 GPT-6 Astra 一个模型，能否迁移到其他前沿模型、对小网络之外的规模是否成立，都还是开放问题。

八、我的四点判断

1. 真正的新鲜事，是「读权重」而不是「写训练代码」。让 LLM 写训练循环、调超参是老故事；让它不借助优化器、纯靠推理直接读写权重矩阵，才是这篇文章真正的分水岭。如果这条路成立，它动摇的是一个延续了三十年的隐含前提：「优化可微网络」只能由符号算法来做。

2. 先别信「打爆 PPO」的叙事，先看它到底做了什么。MinAtar 上 Astra 一次生成的网络碾压 PPO 1 亿步，很惊艳，但那些是 600 参数的玩具网络、规则清晰的游戏——恰好是 LLM 能用语言推理「程序化」的甜区。真正的问题是这种能力能否在规模、任务复杂性上继续成立，而这篇文章自己都还没回答。把它当「方向信号」看，比当「结论」看更稳。

3. 它对可解释性和安全是两个相反方向的加速器。「无评估审计」「从权重里读 backdoor」是防御侧的巨大想象空间；但「零数据能力注入」「递归自我改进」「跨架构嫁接电路」同时也是攻击面和失控面的放大。一个能读懂并改写任意网络权重的通用模型，本身就是一个双刃工具——它让「打开黑盒」和「精准植入」同时变便宜了。

4. 值得盯的下一件事，是那个 benchmark。这篇博客最有诚意的部分，是作者没有停在「看我们多厉害」的 demo 叙事，而是明说要建 benchmark 和 harness、把「黑魔法」变成可复现的工程学科。Weight-Space Programming 到底是「真实的范式转折」还是「又一个被 cherry-pick 的 demo」，最终会由那个基准说了算。等它出来，才是检验这一切含金量的时候。
