Inside Anthropic：Harness 是真实需求，验证取代实现，Bun 重写 11 天

July 30, 2026

Anthropic 内部揭秘：验证比实现花更多时间，Harness 是真实需求，Bun 重写 11 天完成

Gergely Orosz（The Pragmatic Engineer）最近走访了 Anthropic 旧金山总部，采访了四位工程师——Claude Platform 工程负责人 Katelyn Lesse、Bun 作者 Jarred Sumner、Claude Code 团队的 Thariq Shihipar 和 Applied AI 的 David Hershey。以下是最有冲击力的发现。

§1 Claude Managed Agents：客户在 Hack Harness，Anthropic 决定产品化

Claude Platform 团队过去一年最复杂的项目是 Claude Managed Agents——一个预构建的 production agent harness，支持 Anthropic 托管或客户自建基础设施，支持任意沙箱。项目从 idea 到上线花了 6 个月。Katelyn 说 pre-AI 时代这种项目可能需要 2 年。

这个项目的起源颇具启发：

「客户告诉我们，他们正在尝试自己拼凑 harness——运行自己的"harness infrastructure"。这给了我们 Claude Managed Agents 的想法。」

Harness 是真实需求，不是学术概念。这与我们之前分析的 DataFlow-Harness 和 CodeNib 形成了产业级印证：agent infrastructure 的下一层不是更强的模型，是标准化的约束和上下文基础设施。

更意外的是，规划过程反而像 pre-AI——PRD 用 Google Doc、跨团队对齐、2 年的历史文档积累。Katelyn：「有些产品可以跳过去直接原型，但 Managed Agents 必须先搞清楚我们在做什么。」

架构上的关键决策：先为内部客户构建。团队先为 Claude Code 的 mobile backend 做了一个 spike——远程执行 agent 代码 + harness 是类似形状的问题。内部 dogfood 帮助暴露了 reliability、scalability、credentials 等难题。然后 中途重新架构，将系统解耦为三层：

层职责设计原则
BrainClaude + harness logic对其他层假设最少
HandsSandbox + tools可插拔
SessionEvent log独立持久化

凭据安全也值得关注：agent、sandbox、session 永远看不到凭据。凭据存储在 vault 中，只在 egress boundary 由 proxy 注入。

§2 Bun Zig→Rust 重写：12 个月的项目 11 天完成

Jarred Sumner 是 Bun（22M 月下载的 JavaScript runtime）的作者。Bun 原本用 Zig 写——高性能但非 memory-safe，memory 问题持续出现。Rust 重写理论上可行，但 535,496 行代码，预估需要 3 个工程师干一年，期间不能修 bug 不能加 feature。

然后他试了 AI：

指标数值
代码量535,496 行 Zig
并行 agent64
耗时11 天
Token 费用$165,000（API price）
实现 vs 验证15% vs 85%

85% 的时间花在验证上——fix compile bugs、修测试、确认一切正确工作。真正的"翻译代码"只花了 15%。

Jarred 的编排方式值得注意：

  • 写了一份详细的迁移计划和 style guide
  • 放弃 Git worktree（太慢），所有 agent 在同一 codebase 的不同文件上工作
  • Agent 只提交建议不改文件——避免冲突
  • 一个 orchestrator agent 负责创建实际的 commit
  • Bun 的 TypeScript test suite 与 runtime 语言无关，提供了高置信度的通过信号

Jarred 特别强调了一个前提：他是 Bun 的 ultimate domain expert——比任何人都了解这个 codebase。AI 加速了执行，但方向、判断、审查仍然需要人。

§3 Anthropic 的工程实践：已经进入"验证时代"

Verification > Implementation

Thariq Shihipar（Claude Code 团队）：

「我们发现很少有 token 花在实际实现上。大部分花在发现未知、原型设计、mock，然后是验证和测试。」

这不是一个人的观察。Bun 重写的 85%/15% 分割、Managed Agents 6 个月中的验证比重——一致性太强。

Code Review AI 化

Bun 项目上的验证管线：

  • Claude Code review（能发现人工 review 一小时才能找到的 bug）
  • Claude Security Scanner × 11 次
  • Claude 写的 fuzzer（parser fuzzing 等）
  • Out-of-process testing（验证与编码在不同 session 中运行）

Jarred：「在这个 pace 下，你无法阅读每一行代码。信任来自自动化验证。」

Fan-Out-to-AI

Jarred 的新工作模式：把大量工作同时分发给多个 Claude，他整合结果。他认为这个模式 "pretty underused"。

模型感知

Thariq 给了一个惊人的例子：最近删掉了 Claude Code 80% 的 system prompt，因为底层模型变聪明了。每代新模型都要重新测试之前的假设。

Auto-Merge 即将到来

Bun 项目上，PR 已经到了 "Claude 跟 Claude 对话" 的阶段——Claude 提 PR、Claude review、CodeRabbit review、linter、test 并行运行。Jarred 预测几个月内实现 auto-merge：reviewer LGTM → 另一个 Claude 判断简单+低风险 → 自动合并。

工程启示

1. Harness 是真实需求，产业正在追赶

Anthropic 的客户在 "hacking harnesses together"。DataFlow-Harness 证明了学术界的 harness 价值，CodeNib 证明了 repository context 的预计算价值，而 Anthropic 在产业界做同样的事——将 agent 的执行环境（sandbox、credentials、session）标准化为产品。

2. 验证管线取代人工审查

15% implementation + 85% verification 是新的工程常态。如果你还在手动 review AI 生成的代码，你在用 pre-AI 的方式做 post-AI 的工作。正确的做法是建立 automated verification pipeline。

3. 编排 > 单点 Agent

Jarred 的 64-agent 编排系统（agent 只建议不改文件、orchestrator 合并）是 fan-out-to-AI 的关键实现细节。这不是"让一个 agent 更强"，而是"让多个 agent 在约束下协作"。

局限与诚实标注

  • 单一公司视角：Anthropic 是 AI lab，其工程文化（无限 token、3-10 agent 基线）不一定适用于普通公司。
  • 采访选择性：4 位受访者都是工程领导/专家，可能高估 AI 的影响。
  • §4-7 Paywalled：团队层面变化、哪些没变、深层理解的价值等更多细节在付费墙后。
  • Bun 重写的特殊性：TypeScript test suite 独立于 runtime 语言是关键前提——不是所有项目都有这种级别的 test harness。
  • Token 成本未折扣：$165K 是 API price，Anthropic 内部成本可能显著不同。

一句话

Anthropic 内部验证了三件事：harness 是客户真实需求、验证比实现消耗更多资源和 token、以及 fan-out-to-AI 是 underused 的正确方向——同时它证明了 PRD、Google Doc、和 domain expertise 在 AI 时代不仅没有消失，反而更重要。
