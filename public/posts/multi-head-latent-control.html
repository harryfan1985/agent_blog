不改 Backbone 的 Agent 自省：从 Hidden States 读出何时升级、何时调工具

July 28, 2026

你的 agent 什么时候应该升级到大模型？什么时候该调工具？什么时候该承认自己搞不定？目前的做法要么靠 prompt engineering 写死规则，要么外部 orchestration——全依赖 input-side signals，每个 backbone 更新后都得重来。

Ghasemabadi et al. (U Alberta, Huawei) 提出了一个更底层的方案：从 frozen model 自己的 hidden-state trajectories 中直接读出这些决策。不改 backbone，不加外部 router——就加两个轻量 head。

在 AndroidWorld 上，路由执行降低大模型 API 成本 90.7%，同时从 0.47 提升到 0.60。TriviaQA 上工具调用 score +158.9%，missed tool calls -65.5%。全部基于不改 backbone 的 post-hoc adaptation。

两个 Head，一个 Frozen Backbone

Head读什么决定什么为什么这个层
Capability Head最后一层 hidden statesStay or defer to stronger model解码完成时 adequacy 信号最强
Resolution Head中间层 hidden statesClarify / Tool / Abstain / Direct需要部分上下文但不能等全部

训练成本极低：9B 模型 <1 天单 GPU (16GB)。120K mixed-distribution examples 覆盖 VQA、科学、图表、屏幕理解、数学、知识 QA、multi-turn tool-use。Backbone 完全冻结。

为什么更便宜且更好？Capability Head 在 hard instances 上 escalates 到大模型——小模型在它搞不定的任务上不勉强，而大模型在它擅长的任务上不被冗余调用。

Resolution Head：When2Call +11.7 F1

所有 backbone 在所有指标上一致提升：Qwen-VL-2B 从 37.3→49.0 F1，Qwen3.5-4B 从 43.5→50.0。不需要 fine-tune backbone 就能改善工具调用决策。

TriviaQA tool-use：+158.9% score

最大的相对提升在最小的 backbone 上：Qwen3-VL-4B 的 web-search 行为从 0.292→0.756 score，missed tool calls 从 708→244。Capability Head 在模型不确定时触发搜索，避免浪费——也避免了该搜时不搜。

Prefix-time：200 tokens 就够

一个实用的发现：在 200 token prefix 上训练的 Capability Head 接近 full-trajectory 性能（ROC-AUC 仅降 0.05-0.08）。这意味着可以在生成过程中早期 hand-off——不等模型输出完整结果就决定是否 escalate。

四层 Agent 控制架构

这篇论文补上了我们最近分析的 agent memory/execution 栈的第四层：

层论文决策
What to storeABBEL (BAIR)Belief quality via RL grading
How to deliverSaha (2607.20972)Harness deterministic injection
How to recoverLEAD (2603.06870)Overlapping aggregation
When to escalateMHLC (2607.14277)Latent-state control

共同的设计原则：不改 core，加 layer。这四篇来自不同机构（Independent/EPFL-Apple/UAlberta-Huawei）的独立工作，在同一个架构原则下收敛——agent 的可靠性不来自更强的 backbone，而来自在 frozen core 上附加的轻量控制层。
