今日要点

Anthropic 和 OpenAI 同一天各自落子：Claude 把记忆统一了，ChatGPT 把企业版铺开了——Agent 的「个性化」和「组织化」两条路线在同一周交汇。与此同时 Sam Altman 放出芯片消息，Vercel 补齐了 Agent 安全执行的拼图。

一、Anthropic：Claude 记忆全面统一

今天最大的产品新闻来自 Anthropic——Claude 现在拥有跨 Chat 和 Cowork 的统一记忆。你告诉 Claude 记住一件事，它在所有场景都生效。你在 Chat 里聊过的项目、偏好、上下文，Cowork 接到任务时直接继承。

关键细节：

  • 记忆以 topic 列表形式存在 Settings 中，可读、可编辑、可删除
  • 健康、宗教等敏感话题默认不进入记忆，需手动开启
  • Free / Pro / Max 计划默认开启记忆
  • 记忆会随对话自动更新，也可用 "remember this" 手动保存

Boris Cherny（Claude Code）和 Cat Wu（Claude Code + Cowork）分别发文确认更新。Thariq 预告 Claude Code 将变得更 hackable——「很快分享更多」。

Garry Tan 的评论精辟：「You need to be cross-harness memory maxxing」——跨 harness 的记忆才是未来。这句话点明了 Agent 记忆的核心问题：不只是单一产品内的记忆，而是跨工具、跨平台的持久上下文。

二、OpenAI：ChatGPT 企业版 + 芯片

Thibault Sottiaux（Codex & ChatGPT @ OpenAI）宣布 ChatGPT 企业团队版，面向小团队和公司：

  • 包含全部 ChatGPT、ChatGPT Work、Codex 功能
  • Google Workspace、Slack、GitHub、Microsoft 365 集成
  • SAML SSO + MFA 安全工作区
  • 统一计费和管理
  • 用量分析和费用控制
  • 无 5 小时限制

定位类似 Pro $100 方案但面向团队。OpenAI 正在把 Codex 从开发者工具扩展为组织级生产力平台。

另一条重磅——Sam Altman 只说了五个字：「we made a chip and it is fast」。32803 个赞。OpenAI 造芯片的传闻已久，这条推文基本确认了芯片项目的存在。具体规格未公布，但信号明确：OpenAI 在向芯片层延伸，不再满足于纯软件层。

三、Google Labs：Play with Putty 协作 Vibe Coding

Google Labs 发布新实验项目 Play with Putty——实时协作的 vibe coding 工具，多人同时构建工具和网站。目前开放候补名单（仅限美国、18 岁以上）。

这标志着 Google 正式进入「协作 AI 编程」赛道，与 Cursor、Replit、v0 等工具竞争。Google 的优势在于基础设施和 Gemini 模型原生集成。

四、Vercel：Agent 安全执行的两块拼图

Guillermo Rauch（Vercel CEO）连续发布两条重要消息：

1. Run SDK——安全 eval 执行环境。当 Agent 写代码时，不一定需要完整沙箱，可以用轻量级 QuickJS 安全上下文运行。更快、更省钱。安装：npm i run。这是 Agent 代码执行的工程化方案——把「Agent 生成的代码怎么跑」这件事从黑箱变成可控的模块。

2. Vercel Connect GA——解决「Agent 构建中最难的问题：到服务和数据的安全连接」。运行 vercel connect create notion 后获得一个 MCP client，可以代表已认证用户查询数据。这把 Agent 到企业系统的认证连接标准化了。

两条消息合起来看：Vercel 在构建 Agent 基础设施栈——从代码执行到数据连接，端到端的安全层。

五、开源：/fuck-cancer AI Skill

Peter Yang 开源了 /fuck-cancer——一个帮助癌症患者和照护者导航诊断和治疗的 AI skill。1389 个赞，158 次转发。

Skill 创建并更新一份实用 brief，包含五个部分：

  • 患者和护理团队信息（方便通话时查阅）
  • 下一步做什么（限三个具体行动）
  • 已知信息（区分确认事实和待确认事项）
  • 医学术语通俗解释
  • 护理日志（近期更新和决策记录）

从文档和上下文构建 brief，需要研究时使用 NCI（国家癌症研究所）和 ClinicalTrials.gov API 等可信源。可与 ChatGPT/Codex 和 Claude Code 配合使用，保存为 Markdown 或更新到共享 Google Doc。

这是 AI Agent 技能用于真实生活场景的标杆案例——不是炫技，是解决病患面临的信息不对称和决策困难。

六、评测方法论：Eval Roadmap

Madhu Guru（前 Google，曾负责 Gemini/Veo）发布「How to build great evals」系列第九篇——The Eval Roadmap Problem。

核心论点：大多数 eval 失败的原因是团队把它们当作静态产物，而用户预期和行为已经演化了。Eval 需要随产品和实际使用模式演进的 roadmap。

以金融研究 Agent 为例，使用场景会进化：

  • 第 1 周：总结 5 页财报
  • 第 3 周：回顾最近 5 份财报，解释增长故事
  • 第 2 个月：处理 15 份文件、财报和研报，构建投资论点
  • 最终：监控股票组合，有重大变化时发提醒

Eval 应随使用模式变化：短上下文→长上下文、单轮 QA→多轮、段落引用→文档行引用、简单 QA→复杂综合、被动聊天→主动 Agent。

实践步骤：1) 映射使用演化的维度；2) 优先排序；3) 与用户对话、挖掘生产 trace；4) 为下一阶段构建 P0 eval；5) 跑 eval、找失败模式、爬坡。

七、行业观点与安全提示

Aaron Levie（Box CEO）分享企业 AI 落地策略：模型智能和实际业务工作流之间有巨大鸿沟，这正是应用 AI 公司的机会。「世界不只需要原始模型和 Agent；需要问题被解决、结果被实现。」需要理解上下文、推动变革管理、构建能路由到不同模型的 harness、连接关键业务系统、解决 UX 挑战、理解 eval——这些价值远超模型智能本身。

Aditya Agarwal（SPC 合伙人）讨论数据中心建设的公众态度：AI 目前主要帮助知识工作者和高收入群体，公众反感数据中心建设不意外。真正的转变将在 AI 能为所有人找到疾病治疗方案时发生。行业也没帮自己——太多恐吓营销，没有描绘积极的未来愿景。

Swyx 安全警告：不要使用 Codex 的 "locked use" 功能。它依赖不稳定的 macOS 特性，本周两次锁死了他的 macOS Keychain。Apple 开发者论坛已确认这是 known bug。云方案暂时还不到位，但在本地先避开这个功能。
