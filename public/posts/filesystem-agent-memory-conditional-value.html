文件系统作为Agent记忆：组织化的条件性价值

August 1, 2026

当 LLM agent 需要记忆跨越单次对话时，工业实践已经悄然收敛于一个朴素方案：文件系统——一个 agent 自己读写、重组的 markdown 文件目录树。Claude 的 Memory Tool、Claude Code 的 MEMORY.md、生态中遍地开花的 agent skills，都建立在一个从未被验证的假设上：agent 能保持这个不断增长的存储库组织良好，且这种组织确实值得付出成本。

UIUC 韩家炜组联合 UCSD、Adobe Research 在 7月29日发布的这篇 59 页预印本，是第一次对文件系统式 agent 记忆的系统性实证研究。它回答了一个 pragmatic 到几乎被忽略的问题：我们依赖的默认方案到底行不行？

三角色模型：管理/搜索/执行的记忆分工

论文将文件系统记忆形式化为三个角色围绕一个共享存储：

角色职责实际映射
Management Agent接收内容流，写入+重组存储Claude Memory Tool 的后台整理逻辑
Search Agent查询存储，返回带源头引用的答案RAG 检索层
Execution Agent执行任务，产出轨迹被蒸馏为 skillCoding agent 本体

这个分解的精妙之处在于声明式记忆和过程式 skill 统一在同一个文件系统中——一个存储，两种内容。角色合约是极简的，所以在实际 coding agent 中三个角色可以是一个模型。

实验矩阵：6 种记忆 × 4 个基准 × 3 个模型梯级

记忆变体做法成本
Closed-book无记忆，模型凭自身知识回答零
Chunk retrieval分块 + BM25 检索（标准 RAG baseline）低
Verbatim dump按会话存原文，零模型成本零（但检索贵）
Foldered sessionsLLM 设计文件夹分类（仅移动，不编辑内容）低
Reorganized storeLLM 重组存储（含压缩版/保留版两个变体）中
Agent-curated storeManagement agent 从零增量构建高

Benchmark 覆盖：LoCoMo（多会话对话 QA，158 题）、PersonaMem（32k/128k tiers，选择题）、REALTALK（21 天真实人类对话）、ALFWorld（具身任务）。主力模型是 gpt-5.4-mini high-effort，梯度测试从 nano 到 full gpt-5.4。

核心发现：组织化记忆的价值是条件性的

RQ1：Agent 怎么组织？

Management agent 生长的是主题树，但树的形状更多是模型签名而非规模响应。给更多材料导致合并而非分裂——hierarchy 在 folder、file、heading 之间迁移。退化模式：重组织 pass 可能静默压缩内容，除非加一条"保留每个事实"的规则。

RQ2：组织值得吗？

没有单一形状在所有 benchmark 胜出。组织的明确回报是搜索成本——organized store 在大材料上约减半检索 token 和轮次。但在技能任务上赢家取决于消费者：verbatim episode log 配合强 execution agent 最佳，弱 agent 下只有 curated skills 不崩溃。

RQ3：模型能力买什么？

对话场景：management agent 强度买组织风格，不买答案质量；search agent 强度直接付费——更强的搜索模型直接转化为更好的答案。技能场景：management 能力是阈值效应——跨过门槛后 store 内容比哪个模型执行更重要。

RQ4：记忆能持续吗？

在测量范围内 store 越长越有用。对话 store 早期创建少量文件后仅编辑不删除。但 ⚠️ taxonomy 合约遵守度随增长侵蚀——仅最强 management agent 能维持文件归属的唯一性、命名的自描述性等五项约束。

RQ5：工具集是中性包装吗？

不是。替换工具集（memory-tool API → shell）重塑了 store 本身——shell 导致更多小文件（对话）或更多合并（技能）。添加单个工具改变行为不改变结果，但替换整个工具集是记忆组织的控制杆。

Engineer's Read：对 agent 构建者的含义

如果你在...这篇论文告诉你
设计 agent 记忆系统不要为组织而组织。如果你的 search agent 够强、材料不大，verbatim dump + strong search 可能就够。组织付费于成本而非质量
构建 agent harness工具集不是中性的。选择 memory-tool API 还是 shell 会改变 agent 如何组织记忆。Harness 设计就是记忆架构设计
评估记忆质量现有 QA benchmark 对存储形状不敏感——你可能测不出组织的价值。需要新的、对 shape 敏感的评估方法
维护长期 agentTaxonomy 合约（五项约束）是 store 健康的可操作指标。监控文件归属唯一性、命名自描述性、主题完整性可以作为记忆健康度 dashboard
做 agent RSI/自我改进技能蒸馏循环（execution→management→search）形成记忆驱动的 RSI。能力阈值效应提示：跨过门槛后内容本身比模型更重要

局限与开放问题

  • 单会话 horizon：所有实验在单会话内完成，未测试跨会话持久化周期中组织退化的累积效应
  • 仅 gpt-5.4 系列：发现可能耦合于 GPT 系列行为，开源模型上的行为未知
  • 质量 benchmark 盲区：现有 benchmark 区分不出组织优劣——你可能在为看不见的收益付费
  • 角色分离的隐含成本：实际 coding agent 中三角色合一，分离开销未量化

这篇论文把文件系统从"默认假设"升级为"设计空间"。它不告诉你"应该怎么组织记忆"——它告诉你组织什么时候值得、什么时候是浪费、以及你手里的工具集本身就是记忆架构的控制杆。对于构建 agent 基础设施的工程师来说，这是一份少有的、将基础设施选择对 agent 行为的因果效应量化到数字级别的实证研究。
