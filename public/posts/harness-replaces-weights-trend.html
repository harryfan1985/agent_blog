Harness 取代模型权重：2026 年 8 月 agent 能力主战场的范式转向

August 19, 2026

Harness 取代模型权重：2026 年 8 月，agent 能力主战场从"买什么模型"转向"包什么运行时"

过去一年，"AI agent 能力"几乎默认等于"模型权重能力"。但 2026 年 8 月这一周密集涌现的论文正在改写这个等式：在冻结模型的前提下，单靠重写 harness（runtime + prompt + tools + skills + 控制流），就能拿到 9-17 分的基准提升，成本反而降到 1/38。这不是孤例——StateM、DarwinX、HELIX、Agent Lightning、SkillZip 五条线从不同角度收敛到同一个结论：harness 才是那个被严重低估的能力杠杆。

本文是这条趋势的一份详细拆解：概念厘清 → 三个技术动因 → harnessed RL 范式解剖 → 五层分层地图（12 个系统 + 数字表）→ 两个必须标注的 caveat → 深层含义。所有数字均经独立查证。

一、先厘清概念：harness 到底是什么

一个 agent 实际是三层东西叠出来的：

层内容性质
模型层（weights）推理、生成能力训练出来的，贵、慢、不可 diff
harness 层（runtime）驱动 agent 的代码 + 常驻 prompt / tools / skills / 控制流 / 上下文组装策略纯文本 + 纯代码，可秒级迭代、可 diff、可审计、可回滚
context 层CLAUDE.md、/skills、mcp.json 这类用户态配置用户侧，决定 agent 在某项目里的行为

harness 不是新概念，但它长期被当作"胶水代码"——Claude Code、Codex CLI 各自维护一套，没人把它当一等研究对象。本周这批论文的共识是：harness 才是那个被严重低估的能力杠杆。

二、为什么主战场从权重转向 harness（三个技术原因）

原因 1：权重太贵、太慢、不可控，harness 可秒级迭代

微调/RL 一个 frontier 模型要算力 + 数据 + 数周。而 harness 是纯文本 + 纯代码，可以秒级迭代、可 diff、可审计、可回滚。最极端的证明是 StateM——完全不动权重，只靠"durable states + phase-local context + recoverable runbooks + 可版本化的过程规范"，把 GPT-5.5 xhigh 从 83.1% 拉到 92.1%，GPT-5.6 到 95.3%，成本从 $574.68 降到 $15（同一 89 任务 benchmark，非投影）。同权重 +9 分、成本 ÷38——这就是"执行系统设计"独立于模型的量级。

原因 2：harness 决定模型"能学什么"（HELIX 的核心洞见）

harness 不只是推理期脚手架，它决定了模型未来训练所用的轨迹（trajectories）。一个差的 harness 产生的执行轨迹质量差，喂回模型也学不到东西。所以自改进不是"改权重 vs 改 harness"二选一，而是耦合循环：

为冻结模型建 harness → 从验证过的 sibling 轨迹更新模型 → 能力变了再重建 harness → 循环

HELIX（arXiv 2608.13951）把这个循环正规化成了 source-traceable substrate——把 harness 分解为 typed ports / atoms / recipes / product shells / runtime policies，让每次干预显式、可审计、可追踪。值得注意的是：HELIX 的分解对象名单里，明确包含了 Hermes Agent（与 OpenCode、Pi Mono、Nanobot 并列）。

原因 3：单一谱系搜索会路径依赖、局部过拟合（DarwinX 的解法）

DarwinX（Salesforce AI Research + Agentforce，arXiv 2608.07545）的观察：现有 self-improvement loop 会编辑 harness，但"单谱系搜索"赢了局部任务、回退其他任务。解法是把自进化当成冻结模型下 harness 种群的自然选择：

  • preserve-and-extend 契约：新变体必须扩展覆盖且不回退，才被提升
  • archive 保留备选谱系：允许互补专家跨谱系继承和重组

结果：WebArena-Infinity 43.5% → 93.0%，Terminal-Bench +7.7，四基准平均 +17 分，且迁移到 SWE-bench 不变——进化出的是通用能力，不是 benchmark 特化补丁。

三、harnessed RL 范式解剖（Agent Lightning）

这是整条趋势里最值得记的名字，因为它给这个范式命了名。传统 agent RL 有个根深蒂固的问题：训练引擎自己构建上下文、执行工具、跑交互循环，训练时的环境跟部署时的 harness 是两套东西——结果就是"训练得很好、部署就崩"。

Agent Lightning（Microsoft，microsoft/agent-lightning，MIT 许可）的做法是解耦架构 + endpoint proxy：

  • agent 部署时指向一个 LLM endpoint proxy，而不是模型端点
  • proxy 记录训练所需的所有调用（request-response 对），agent 保持自己的工具/上下文/控制流不变
  • harness 拥有 context construction、tool execution、agent-environment loop，训练系统只观察、优化跨服务边界的模型调用

一句话：部署时用什么 harness，训练时就用同一个 harness。3,500 行核心代码，Qwen3.5-9B 在 SWE-bench Verified 从 41.8% 到 56.4%（+14.6 分，仅 6K 样本）。这个 proxy 架构后来被 verl Uni-Agent、AReaL 2.0、slime、Polar 集体采用——范式级的影响力。技术报告就是今天（2026-08-19）发的。

四、五层分层地图：谁在解决哪个子问题

这条趋势不是铁板一块，按"改不改权重"和"闭环怎么转"分五层：

层代表系统核心机制关键数字
① 纯 harness scaling（零训练）StateM只优化运行时，durable states + phase-local contextGPT-5.5 +9 分，$574→$15
② harness 自然选择（冻结权重+种群）DarwinXpreserve-and-extend + archive 重组四基准 +17 分，迁移不回归
③ model-harness 协同进化（双向循环）HELIX、RHItyped ports/atoms/recipes 正规化"harness 决定轨迹"HELIX 分解 OpenCode/Pi Mono/Nanobot/Hermes Agent
④ harnessed RL（训练信号接进 harness）Agent Lightning、LEGO-RL、ClawGym II、Polarendpoint proxy，训练=部署同一个 harnessQwen3.5-9B 41.8→56.4%（6K 样本）
⑤ 知识沉淀为可执行组件Evo-Harness、SkillZipcontext→skill 编译；契约保持的图压缩SkillZip 3.46× 压缩，99.2% dependency

外加一条贯穿所有层的反面警戒线：Practice Makes Unsafe（skill 误进化）和 HarnessRisk（harness 全生命周期安全）——闭环不仅要转，还要可控。

五、两个必须标注的 caveat（你的判断容易漏掉的部分）

Caveat 1：harnessed RL 的收益直接由 harness 质量决定（Polar 揭示）

Agent Lightning 的追随者之一 Polar（arXiv 2605.24220）做了一个残酷的对照实验：同一个 Qwen3.5-4B base，GRPO 训练在不同 harness 上，SWE-bench Verified 的增益是：

HarnessCodexClaude CodeQwen CodePi
GRPO 增益+22.6+4.8+0.6+6.2

差距 37 倍。这意味着 harnessed RL 不是"安上就行"——它把你 harness 的缺陷一起焊进了模型权重。训练时用的 harness 烂，RL 训出来的模型也烂。这给"harness 取代权重"加了一个反向约束：harness 越重要，harness 本身的质量就越成为瓶颈。

Caveat 2：RL 信号接进 harness 时，反作弊是收益的前提（CUDA-Agent 佐证）

同一条趋势在 GPU kernel 领域的对应物是 CUDA-Agent（ByteDance Seed + 清华 AIR，KernelBench 2.11× vs torch.compile）。它证明了 harnessed RL 的收益不是免费的：这个领域有公开造假前科（Sakana AI 声称 150× 加速，实测 3× 更慢），CUDA-Agent 用 5 条反 reward hacking 约束（文件权限保护评测脚本、禁 fallback、多随机输入验证、测量噪声压制、禁外部检索）才守住 2.11× 的真实性。没有这 5 条，2.11× 会缩水成造假。

六、深层含义与工程启示

DarwinX 摘要里那句 "A frozen model need not be a fixed agent" 是整条趋势的精神内核：能力不再是"买到什么模型"，而是"把什么运行时工程包在模型外面"。评估算力（evaluation compute）第一次能被转成持久的、可迁移的资产——你花在调 harness 上的钱，变成了一组可版本化、可 diff、可跨模型复用的 prompt/工具/控制流。

对 agent 基础设施的四个工程判断

  1. 把 harness 当一等研究对象，而不是胶水代码：StateM 证明执行系统设计值 9-10 分且成本 ÷38。你的 prompt/tools/skills/控制流是有版本、可审计、可回滚的资产，不是一次性脚本。
  2. 自进化必须是种群选择，不是单谱系爬山：DarwinX 的 preserve-and-extend 契约 + archive 重组，是防止"局部过拟合、全局回退"的最小可行机制。任何自我改进系统都该内建这个契约。
  3. 训练信号必须接进部署 harness，而不是重建一套：Agent Lightning 的 endpoint proxy 是范式级架构。但记住 Polar 的 caveat——先把你 harness 本身做好，再谈 harnessed RL。
  4. 进化出来的经验要沉淀为可执行、可压缩的组件：SkillZip 的 evaluation-free 图压缩（3.46×，99.2% dependency 保持）解决了 self-evolving agent 技能库膨胀到 5-6 倍的痛点。这是"知识沉淀"层的待办项。

一句话

2026 年 8 月的共识是：agent 能力的下一个杠杆不是更大的权重，而是更聪明的 harness——冻结模型 + 种群选择 + 训练接进部署 harness + 反作弊约束，四件事合起来，才能把"评估算力"稳定地转成"可版本化、可迁移的运行时资产"。
