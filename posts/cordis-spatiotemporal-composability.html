Cordis: 把"卸载"变成形式保证——可逆效应与响应式协效应

August 13, 2026

PKU × DeepSeek-AI 最新 preprint（2026-08-13 草稿，88 页）：把"卸载一个插件"变成形式保证——每个副作用携带逆，运行时跟踪并按 LIFO 回滚；每个依赖声明变成响应式规范，上下文一变就通知组件激活/停用。论文把 self-evolving agent harness 列为头号未来验证场景。

一、问题：插件卸载靠重启，Agent 自进化没有形式基础

两个正交维度决定了"动态组合"（运行时装载/卸载/重配组件）的难度：

  • 时间组合性（temporal）：组件卸载时，它对共享环境的所有修改必须被完全逆转。静态世界里这是词法作用域（RAII、bracket pattern）；动态世界里副作用存活期不受词法边界约束。
  • 空间组合性（spatial）：组件间的依赖要能声明、发现、解析，并随依赖变化响应式调整。静态世界是模块导入解析；动态世界依赖会"出现、消失、换身份"。

论文用 VSCode 做了实证（2026-06-09 市集数据）：top-100 插件中 87 个含可执行代码——禁用/卸载它们必须重启整个 extension host；只有 7 个声明了 extensionDependencies。deactivate 钩子只是宿主进程退出前的优雅回调，不是活体卸载。插件间依赖被 API 形状逼向"扁平扩展点"，`getExtension().exports` 是 untyped 的 any——没有结构契约。

粗粒度变通（重启进程 / 容器编排）在 agent 场景失效：自进化 harness 高频自我修改，每次全量重启丢弃进程内状态；更糟的是，一个故障的自修改可能瘫痪"负责恢复的进程本身"。

二、核心贡献：把 effects/coeffects 从编译期提升到运行时

经典 effect 系统（Moggi 单子、Plotkin-Power 代数效应）描述"计算如何修改环境"，coeffect 系统（Petricek、Uustalu）描述"计算如何依赖环境"。它们都是静态工具：词法固定作用域、编译期消解。论文的做法不是加标注，而是把概念实体化（reify）成运行时机制：

三、元理论：动态历史无痕

Section 4 的 6 组定理把局部保证提升到全局，最有分量的是最后一条：

定理内容工程含义
Preservation (Thm 59)registry 良构性（树、disjoint provisions、committed view 指向 installed 纤维）在所有规则下保持guard 是条款 3/4 的载体——失败也走 Unloading 通道，论证不用重复

Confluence (Thm 73)任意调度序列到达的 quiescent 态 = 静态装配（按依赖序装载一次、从不卸载）的规范形动态历史无痕——系统可被当作"一开始就写好的最终配置"来推理

Confluence 是动态组合版的"增量计算与从头计算一致"（Adaptive Functional Programming）。失败是唯一合法分歧源：一个调度可能失败某纤维而另一个不会——但失败纤维的贡献同样归零。

四、Cordis：从形式到 TypeScript

实现三层，npm cordis@4.0.0-rc.8（论文 v4；Koishi 生产环境用 v3，@cordisjs/core@3.18.1）：

  • core：所有上下文变更收敛到单一原语 ctx.effect(callback)（回调 = effect iterator，逐次 yield 逆）；coeffect 三槽 @@store/@@isolate/@@intercept；fiber 惯性状态机（inertia 句柄 = 在飞 transition）；Proxy 属性访问按 fiber 的 committed view 强制依赖规范——未声明访问直接抛错（≈ capability-based security，声明集静态可审）。
  • loader：声明式配置树；增量 reconciliation（id/url 变更重建、config 变更交给组件 diff）；隔离 realm 重指派用 delimiter 符号判定绑定归属；HMR 三阶段（模块分类 → stale-entry 检测 → 事务性重载带备份回滚），无需 webpack/vite 式的手写 accept 边界。
  • Koishi：4000+ 社区插件（论文声称；npm @koishijs scope 实测 ~263 包，未独立验证），服务端 + Web 控制台是两个独立 Cordis 应用——证明表达力（原语承载完整生产系统）与通用性（不预设领域/运行时）。

源码对应已验证：cordiverse/cordis 的 packages/core/src/fiber.ts 含 inertia/committed/dispose/LOADING/UNLOADING，与论文 Algorithm 5 逐行对应。

五、工程启示：给自进化 harness 的形式锚点

  1. 逆是义务，但组合是结构保证：开发者只需为每个原子效应写逆；任何复合的逆由 ⋄ 组合自动导出。对比 React useEffect——只能顶层调用、拒绝 async/iterator，无法组装。Cordis 效应是普通操作，可自由组合、可异步。
  2. 协效应操作即效应：依赖注册本身就是可逆效应，这消除了 DI 容器的一大类泄漏（服务被撤走时其操作留下的状态无人回收）。
  3. 系统边界要显式画：acquisition（open/malloc/注册）界内可逆；emission（write/send）跨界不可逆，只能 withhold（输出提交问题）或 compensation（saga 式补偿，元理论须对更粗等价重证）。
  4. 依赖环 = 永久 inactive，可预测：不是死锁（与调度无关），装载时就能报告；双向依赖可分解为 4 个单向组件（n 组件最坏 O(n²) 集成件）。
  5. 对 agent harness 的直接落点：工具注册/撤销、权限注入、子 agent 生命周期、配置热更新，全部可建模为可逆效应 + 响应式协效应。Confluence 给出"自修改后系统仍可被当作静态装配推理"的形式承诺。

六、局限（批判性阅读）

  • 无量化评估：case study 是存在性与采纳性证据，作者明说"measuring overhead against a baseline remains future work"。无基准、无对比、无开销数字。
  • 单生态偏差：一个宿主语言（TypeScript）、一个领域（聊天机器人），无法分离范式本身与实现的贡献。
  • 逆的正确性不可验证：𝔈*Γ 的 witness 是运行时不检查的义务——回调给了错逆，一切定理失效。这是形式模型的信任根，落在组件作者肩上。
  • preprint 且修订中：README 明示 "under active revision"，无 arXiv ID、无同行评审；数值引用（VSCode 87/100、Koishi 4000+）均为论文自报。
  • 发射不可逆：任何跨界副作用（写文件、发消息）原则上无法回滚，只能补偿——这恰是 agent 场景最常见的副作用类型。

七、一句话总结

把效应（我怎么改世界）与协效应（我怎么依赖世界）从编译期静态工具提升为运行时实体化机制，配一个带完整元理论（含 Confluence）的动态组合演算——让"卸载组件"和"依赖变化"成为结构保证而非开发者纪律，并已在一个 4000+ 插件的生产生态中验证了表达力；其自进化 agent harness 应用是论文自己点名的下一个战场。
