HSI：冻结模型自己进化 Agent 脚手架——以及它诚实标出的两条边界

August 23, 2026

问题：Agent 的 harness，部署后就被冻住了

2026 年，给 LLM 套一层 harness（prompt、工具、记忆、验证机制）让它从「文本生成器」变成「可靠的 agent」，已经是行业共识。但一个尴尬的事实是：harness 一旦部署，通常就被当成固定产物——想改进它，得靠工程师手工改 prompt、加工具、调工作流。

能不能反过来，让 harness 自己进化？这是 arXiv 上 8 月 9 日刚挂出的一篇单作者论文 Hierarchical Self-Improvement (HSI)（作者 Tailin Zhou）试图回答的问题。它的答案干净利落，而且——更难得的是——它诚实地标出了这条路的边界。

核心命题：一个冻结的 LLM，同时扮演三个角色——执行任务的 harness、改写 harness 的 evolver、改写 evolver 策略的 meta-evolver，外层用一个冻结锚点锁死，避免「优化器改写自己」的失控。

一、三层作用域：一个模型，三个角色

HSI 最核心的设计，是让同一个冻结的模型 M 运行在三个层级的作用域上，彼此只靠「可编辑的表面 + 工具 + 执行上下文」区分：

层角色编辑对象
Task harness H执行任务任务行为（被重写的对象）
Evolver重写 Hharness 本身
Meta-evolver重写 evolver 的策略代码优化器的策略

关键在于最上层：meta-evolver 之上压着一个冻结外层锚点（frozen outer anchor）。它允许 evolver 改 harness、允许 meta-evolver 改 evolver，但不允许「优化器改写自己」——自修改被严格局部化到「结构化、且经过实证验证的编辑」。

这一步是 HSI 区别于 SICA、HyperAgents 这类完全自指路线的地方：后者把 meta-agent 和 target-agent 融合成一个可编辑的程序，优化器自身也是被修改对象，天然带有无约束自引用的失控风险。HSI 则把「被优化的东西」和「优化器」用层级边界隔开，再在最外层上一把锚。

二、五阶段循环 + thinking-on/off 归因隔离

进化本身是一个五阶段循环：

  • 种子选择（seed selection）——挑出进化的起点
  • 主进化（main evolution）——evolver 重写 harness
  • 提交选择（commit selection）——筛选出有效改动
  • 元进化（meta-evolution）——meta-evolver 更新 evolver 的策略
  • 最佳版本选择（best-version selection）——按「泛化优先」导出部署版本

但真正让我眼前一亮的是第二个设计：thinking-on/off 隔离。任务执行时关掉推理（thinking-off），自修改时打开推理（thinking-on）。这么做的目的很刁钻——把「推理时思考」这个混淆变量从实验结果里彻底剔除，让性能增益只能归因于 harness 本身，而不是模型「多想了一会儿」。

在自改进研究里，这几乎是独一份的严谨。大多数同类工作根本分不清：涨的分到底是 harness 变好了，还是模型在推理阶段多烧了 token。HSI 用一刀切的开/关设计把这个问题摁死了。

三、两条边界：为什么进化不是万能的

HSI 最有价值的部分，可能是它给「harness 进化」这条轴画了两条清楚的天花板：

  • 反馈保真度边界（feedback-fidelity bound）：进化需要信息丰富的奖励信号来筛选候选。奖励太稀疏，进化就筛不动、原地打转。
  • 骨干能力边界（backbone capability bound）：harness 再怎么重设计，也突破不了那个冻结模型的能力上限。harness 是放大器，不是发电机。

这两条边界不是拍脑袋——它们直接对应了下面的实验数据。

四、实验结果：中低难度暴涨，高难度归零

HSI 在 BALROG（长时程文本交互游戏基准，六个环境呈自然难度梯度）上做评测，骨干是全程冻结的 DeepSeek-V4-Flash-Preview。T=5 次外层迭代，每次最多 80 步 react()。

中等难度任务上，harness 进化带来了稳定的原始 % Progress 提升：

环境提升（% Progress）
BabyAI+39.3
Crafter+33.0
TextWorld+25.0
MiniHack+15.0
NLE（最难）+0（零提升）

两个值得玩味的细节：

  • 泛化是真的：用 20% 未见子集做 held-out 评估，BabaIsAI 的 BreakStop 达到 0.98、GoTo 达到 1.00——进化出来的 harness 没有过拟合训练任务。
  • NLE 零提升是刻意保留的负面结果：最难的 roguelike 环境超出骨干能力上限，harness 进化无济于事。这正是「骨干能力边界」的直接实证。多数论文会把这种结果藏起来，HSI 把它当成了第一等贡献。

更关键的是，轨迹分析显示提升来自渐进的 harness 重构（空间抽象、BFS 规划、LLM 引导导航），而不是简单的 prompt 优化——这印证了「进化的是结构，不是措辞」。

五、它在自改进谱系里的位置

过去两年，Agent 自改进这条线很拥挤：Meta-Harness、Self-Harness、HarnessX、DGM、HGM、SICA、HyperAgents、Recursive Agent Harnesses、SkillOpt、RHI……HSI 的附录 B 给了一张全谱系对照表，基本把这批工作扫了一遍。

如果套用 Lilian Weng 的 harness 优化目标递进链：

instruction prompts → structured context → workflow → harness code → optimizer code

HSI 恰好踩在最后两级——evolver 改 harness code，meta-evolver 改 optimizer code。但它和「完全自指」路线（SICA/HyperAgents）的关键分野，就是那道冻结锚点：它允许你进化到 optimizer code，但不允许 optimizer 无约束地改写自己。这算是给「有界自改进」提供了一个干净的工程范本。

结语：一条诚实的增益轴

HSI 的贡献可以浓缩成一句话：在冻结模型下，任务特定的 harness 内生进化是一条可行的增益轴——但只在中低难度、反馈充分的任务上成立，超出骨干能力就失效。

当然，它也有明显的局限：单作者、单骨干、单基准，作者自己也承认「受计算资源限制，非全规模实证研究」，外部效度有待验证；Advanced 子套件只有 3 个任务，样本不足。但恰恰是这种「把边界和负面结果摆到台面上」的诚实，让它比那些「自改进效果拔群」的包装论文更有参考价值。

对做 Agent 工程的人，最实用的一条启示是：别再默认 harness 是死的。如果任务反馈足够密集、难度在模型能力范围内，让 harness 自己进化是值得试的；同时记住那条上限——harness 救不了能力不够的模型。

来源：Hierarchical Self-Improvement: A Framework for Task-Specific Evolvable Agent Harnesses（arXiv:2608.08466，Tailin Zhou，2026-08-09）；代码 github.com/TailinZhou/hsi；BALROG 基准 arXiv:2509.13672。
