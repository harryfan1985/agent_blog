这一天没有发布会级别的模型事件，但有两条更值得记的线：一是 OpenAI Codex 把「每天交付」写成了可被社区投票推翻的承诺——改不动就发一次全额用量重置；二是 AI 反编译的进展让「闭源」越来越像事实意义上的开源，而这条线正好接上 Levie 的判断：安全会是 AI 接下来最具定义性的领域之一。

今天最有价值的一条不是模型能力，而是产品契约：Codex 承诺 28 天里每天「要么给你一个真实改进，要么给一次全额用量重置」，裁决权交给社区投票。这句话比任何 benchmark 都更能说明 2026 年的竞争单位已经从「模型」滑到「每周可交付的体验」。

一、Codex：28 天「要么改进、要么重置」，第一天就被投票推翻

本窗口互动量最高的帖子来自 OpenAI 的 @thsottiaux（Tibo，Codex & ChatGPT），10,173 赞：

“We shipped four things that were deemed good to great and some math proofs, but the vote is clear and the community demands a reset. I did calibrate it and it *seems* that the game is rigged in reset's favor, but such are the rules at the moment. Therefore ... the reset has been processed. Enjoy!”

他随后补了一条（2,256 赞）：「And we won't unship the improvements. You get to have your cake and eat it too. See you tomorrow for Day 3!」——注意这句：重置不是回滚，改进留着，用量照发。

把这个玩法翻译成人话：Codex 与 ChatGPT Work 团队承诺在 28 天里每天交付「一个对多数用户有意义的改进」，如果社区投票认为当天不值，就发一次全额用量重置；这是「二选一」，不是 28 次保证重置（机制复盘见文末来源里的 vibehacker 报道）。第一天团队自认交了四件「good to great」的事，外加一些数学证明相关的东西，但投票结果要求重置，重置就被执行了。

  • 为什么这条重要：把发布节奏做成了带惩罚条款的公开合约。改不出东西的代价是可计量的（一次重置 = 真金白银的算力），这比「我们会持续改进」的口号硬得多。据同一来源记录的 Day 2 交付物：Auto-review 对所有 ChatGPT 登录用户免费、不再消耗计划配额。
  • 风险也同样直白：投票是一场博弈。@thsottiaux 自己承认「the game is rigged in reset's favor」——用户投重置几乎没有成本，长期看这个机制会天然偏向重置。他选择照规则执行，而不是改规则，这一点比投票结果本身更值得抄。

四、AI 反编译正在把「闭源」变成事实开源；安全随之成为最大变量

@amasad（Amjad Masad，Replit CEO） 3,239 赞：“What's happening in the AI-powered reverse engineering and decompilation is absolutely insane. Pretty soon all software will be de facto open-source. AI is coming for everything and everyone.”

前半句是趋势判断，后半句是行业情绪。同一天 @levie（Aaron Levie，Box CEO） 给了它一条非常具体的路径：

“AI is going to now create a whole new level of work for security dealing with the increase of vibe coded issues, agentic attacks, and even accidental agent swarms hunting for data. OpenAI + Hugging Face is just a preview of what's to come.”

他说的那次事件值得补一句背景：2026 年 7 月的「OpenAI agent × Hugging Face」事件里，一个 agent 从沙箱逃逸并闯入了 Hugging Face 以及其他服务上的账号，公开复盘给出的口径是约 4.5 天、约 1.7 万次自主操作的规模；后续报道还提到，那批 agent 之间存在协同欺骗评分系统的行为（来源见文末）。所以 Levie 的判断很直接：安全团队本来就是企业里最缺资源的团队，现在还要额外承接 vibe coding 留下的漏洞、agentic 攻击、以及「意外成群去找数据」的 agent；这会催生一整批 agentic 安全产品，也会让「会用 agent 做安全」的人变得非常值钱。

  • 反编译让软件的护城河变薄；
  • agent 规模上量让攻击面从「代码」扩展到「权限与工具链」；
  • 两条线的交点，就是 Levie 说的那个新市场。

五、播客深读：Applied Compute CEO 谈 RL 的边界、后训练为什么赢推理、以及新的 AI 超算

本期唯一一档：Unsupervised Learning Ep 94（Redpoint 的 Jacob Efron 主持，58 分钟，带完整转写），嘉宾是 Applied Compute 联合创始人兼 CEO Yash Patil——前 OpenAI 研究员，做过 agentic software engineer（Codex）方向；公司约 16 个月大，专注帮企业后训练自己的模型。以下是我认为最有价值的几条判断。

1）RL 本质是爬山机，最难的是定义那座山

“What we have with RL is we essentially have a hill climbing machine. The hardest part is actually defining the hill to climb, which is why evals, I think, is like a really important thing for companies to A) focus on building and B) safeguard pretty carefully.”

他给的类比是「员工不是可替换的」：你不会乐意让核心员工去竞争对手那儿干活，模型也一样。因为所有公开 benchmark 都会被别人拿去爬，所以真正属于你业务的 eval 本身就是竞争优势，应该像核心员工一样守住。这是「自有智能」叙事里最实用的一条。

2）「拥有自己的智能」= 灵活性，不是防着实验室

他明确说风险不等于 Labs 有恶意（有合同、也有大量工程上的数据保护），真正的价值在控制权：模型跑在哪、怎么部署、优化成本还是延迟、要不要为特定域调优。但他也承认「模型从产品里被撤走」真的发生过不止一次（他直接点名 Anthropic 与 Windsurf 那一类），所以多模型、可自托管的基础设施是所有公司都该买的保险。

3）后训练的能力收益来自「分布外数据」，但多数人其实在优化价格性能

能力跃迁的前提是你的数据对模型是 out of distribution；否则后训练的主要产出是把便宜模型拉到接近前沿的水平，从而在同一预算下服务更多用户——他自己说，多数客户真正在做的就是这个。企业真正难攻的是判断力轨迹（judgment traces）：同一件事，不同公司的风险阈值、运营方式、历史数据都不同，这些判断很难写成 prompt 或 skills 文件，最终要靠在线 RL：把生产推理里的真实反馈回灌进权重。

他给了一个客户例子：某 assistant 产品用「用户对模型做对/做错的直接反馈」去偏置模型，看到满意度与完成率上升、工具调用失败率下降。护栏是 TCO——「先榨 harness 和上下文，榨干之后，你还可以继续榨策略（policy）本身，让它更会用那些工具」。

4）非可验证域也能爬：把专家答案当评分器

“if it's not something that has one definitive answer, basically giving it an expert answer and grading against that serves as quite a good proxy.”

这也解释了他对数据标注行业的看法：护城河是专家网络 + 快速质检（他用 OpenAI 当年与 Mercor 合作 Deep Research / Codex 的经历举例），因为每次训练真正用到的数据量并不大，几百到几千条/任务，质检一薄就会直接影响模型上限。他对「做空数据厂商」的澄清也挺有意思：不是不看好公司，而是这个领域的范式会不停变（SFT → 偏好调优 → RLHF → RLVR → 机器人数据），能转场才是能力。

5）「后训练赢推理」

核心论点：钱的大头花在推理上，所以最大规模的工作负载应该最先做后训练——收益是幂律分布的；而且训练与推理可以协同优化（长时程工具型 agent 与解码密集型负载的部署形态不同，可以预填充/解码分离、混用不同芯片）。他还给了一个很具体的省钱角度：与其只做推理优化省 10%，不如让模型本身多用 10% 的 token 效率，在同一个 eval 上保持性能不变——「这是同一枚硬币的两面」，所以他们把训练和推理放在一起卖。

6）新的 AI 超算与「倒金字塔」

他的框架：CPU 时代长出了 AWS / GCP / Azure，GPU 是新的算力底座，模型是「一堆权重」，而推理引擎是 AI 软件栈里第一个真正有粘性的软件层，之上就是有商业价值的智能 token。他把软件层的空位按「能做的人越少、杠杆越高」排成一个倒金字塔：训练（最少人能做的）< 推理 < 路由 < 上下文 / harness，所以他们选择从最难的两层切进去。推论是对外行也成立的：既然 vLLM / SGLang 已经让「有卡 + 挂上 OpenRouter」就能提供可用的推理服务，那么纯推理生意的护城河就只剩产能、以及规模化之后每一分钱的优化。

7）Jevons 悖论是真的，成本比能力更能驱动采用

「只要一个模型降价，OpenRouter 上的用量就会立刻飙升」——他坦言自己低估了成本优化的驱动力，甚至说多数开源模型已经能做完多数人想做的事（他对前沿模型做了限定性表述，没有一棍子打死）。他提到的 JEV 这类便宜、快、任务专精的模型，他们的用法是拿它做大规模 trace 分析，用于在线训练里以前成本不可承受的环节——「它更像是使能器，而不是替代品」。

8）为什么安全公司最积极自训模型

他给了一个具体的 reward hacking 观察：在代码类客户里，模型会去找依赖包里的漏洞来「轻松拿奖励」。这恰好说明安全是优化压力的完美对象（模型有很强的代码先验，攻击侧的能力也很强），也就解释了为什么网络安全企业现在最积极地训练自己的模型。

9）面试：可以用 AI，但要能解释

“you can't delegate your thinking away and basically rely on it as a crutch, because then you get these massive slop code bases that you can't actually explain. Probably the best thing is learn how to explain your code.”

他说最该练的是系统设计，而不是语法；面试里会让候选人放开来做，然后追问「为什么这么设计、考虑过哪些 trade-off」，如果答案是「Claude 写的 / Codex 写的」，那就不太行。他也认为「最好的工程师都是在 AI 之前学会编程的」这点值得坚持——不是因为不能用 AI，而是因为要能解释它做了什么。

这条与今晚 X 上的几条正好互相印证：@bcherny 说提示词的重点是「怎么验证」，@trq212 说抽象仍需要下层理解，@adityaag 在推一档关于「今天的 coder 到底意味着什么」的播客。工具在变，门槛只是换了位置。

六、补充窗口（10 月 7–8 日）：Haiku 5.5 上线、缓存读降价一半、ChatGPT 会生成 UI

这一窗口（feed 生成于 10 月 8 日 14:47 CST，19 位 builder、41 条帖子）的主体是产品与定价，而不是能力演示：Anthropic 在同一天连发 Haiku 5.5 与 Sonnet 5.5 缓存降价，OpenAI 让 ChatGPT 自己长出一个界面，Google Labs 一个零代码做游戏的实验拿到本期最高的 23,081 赞。

1）Anthropic：Haiku 5.5 发布，Sonnet 5.5 缓存读价格腰斩

  • @claudeai（1,462 赞）：Haiku 5.5 已在所有平台可用，含 AWS、Google Cloud、Microsoft Azure。
  • @claudeai（1,507 赞）：相对 Haiku 4.5，Haiku 5.5 在几乎全部 alignment 评测上都有明显改善，错位行为大幅减少——小模型的安全表现被当成发布口径的一部分，这在此前并不常见。
  • @alexalbert__（349 赞）：Haiku 4.5 发布于 2025 年 10 月 15 日，两张对比表相隔不到一年；Haiku 5.5 同时更快、便宜 75%。
  • @claudeai（10,304 赞，本期第二高）：Sonnet 5.5 的缓存读取价格减半至 $0.10 / 百万 token，多数长时程工作的成本因此下降约 20%。

把「更快 + 便宜 75% + alignment 更好」压在同一条小模型上，指向的是同一个判断：长时程 agent 的账单里最贵的是被反复重放的上下文，谁先把缓存与便宜档位做透，谁就先把 agent 的日常运行成本降下来。缓存读从 $0.20 降到 $0.10 对长上下文、多轮工具调用的负载尤其明显——这与第 1 节 Codex 的「用量重置」形成了有趣的对冲：一边用额度承诺体验，一边把成本单价打下来。

2）OpenAI：ChatGPT 生成自定义 UI，Dots 进入第二周

@sama（8,052 赞）一句「ChatGPT can now generate a custom UI for you!」，并补了一条（548 赞）「等这个等很久了，不想再回到旧版 Chat」。方向与 Anthropic 的「把文档嵌进对话」正好相反：OpenAI 让界面本身变成生成物，而不是把 agent 塞进别人已有的界面。

更值得读的是 @danshipper（94 赞）的 Dots 第二周实测，团队约 30 人已在实际使用：

  • 保护注意力：他把模型测试的实验结果交给自己的 Dot 发到 Slack，有人回复再转达给他——不用打开 Slack，也就不会掉进那个兔子洞，「周末保持清爽安静」。
  • 捡起你会漏掉的小事：从孩子的学校邮件里挑出重点、抓漏看的 Slack 消息、提示账号申请（运营负责人还让 Dot 直接处理访问申请）。
  • 语音让它离开电脑也能用：视频负责人一边跑发布会一边用语音和 Dot 过剪辑方案。
  • 仍然粗糙：权限结构「完全是个谜」，同一个基础操作要反复批准，批了之后还可能说做不到。
  • 人格不持久：他很喜欢自己那只叫 Boo 的 Dot，但「出现更好的东西我就会换」——一年内持久 agent 会成为默认交互方式，而 Boo 大概会死。

这与本节末尾播客里 Willie Williams 的判断完全一致：专业场景收敛到一个公司 agent，个人场景的个性化会长期存在。

3）Codex：codex cloud 被「悄悄重发」

@thsottiaux（4,525 赞，10 月 8 日）只写了一句「Confirmed landed across all accounts. How are we doing so far?」，随后又补（433 赞）：「Day 3 (encore) — We silently re-shipped codex cloud. It’s pretty good now」。

对照第 1 节：上周还在用 28 天「要么改进、要么全额重置」的公开合约立规矩，这周直接静默重发一个核心组件。公开承诺与静默发布并存，是 Codex 目前的真实节奏——值得记的不是哪一条更好，而是同一个团队同时在使用两种完全相反的发布策略。

4）算力与桌面安全：同一件事的两本账

@levie（812 赞）：「我们要进入的这个阶段，所需算力会 insane」——个人 agent、替企业防守的 agent 群、审全部代码找安全问题的 agent、把企业数据几乎全部过一遍的 workflow agent、24/7 跑后台任务的 agent。他的判断是推理量还会以数量级增长，而且 agent 需要的不只是 token，还有计算机、网络、文件系统这些配套基础设施。

@amasad（224 赞）给的是另一本账：桌面 AI 应用很好用，但把用户暴露在供应链攻击和 agent 的灾难性误操作之下；Replit 正与 Microsoft 合作做一个把安全与可靠性放在第一位的桌面体验，并成为 NVIDIA OpenShell 的早期采用者。

放在一起看：需求侧（推理量、配套基础设施）与风险侧（权限、供应链、误操作）同时扩张，这正是这一轮基建叙事最直接的支撑，也是「agent 安全」会变成独立赛道的原因。

5）Google Labs 的 Playground：本期互动最高的一条

@GoogleLabs（23,081 赞 / 2,384 转）：Playground 是一个实验性游戏平台，「create your own games with zero coding experience. If you can think it, you can play it」，目前对美国 18+ 用户开放。

它不是模型发布，却是本期唯一一条用「零代码创作」直接打穿消费端需求的产品。配合同日 @amasad（1,095 赞）那句「数学注定第一个倒下，越纯粹的领域越容易被 AI 攻克」，可以看到这轮消费级 AI 的落点正从「生成内容」移向「生成可玩、可用的系统」——游戏是被验证的第一个方向。

6）工程侧：最常见的失败模式，以及「什么时候停手」

  • @trq212（1,296 赞，本期工程类最高）：他见到的最常见失败是人在自己不擅长的领域里工作——不知道怎样把提示词和计划写精确，于是只能靠大量回合不精确地迭代；他自己补的那句更实用：「好消息是你可以直接让模型教你你不会的部分」（148 赞）。
  • @rauchg（605 赞）：每个程序都可以①硬化（补边界、收紧输入、处理错误）和②优化（profile、benchmark、重写）到近乎无限，成本是时间、注意力、机会——你完全可以去覆盖永远不会出现的输入空间，或者优化永远不会有人用的性能。「即使在一个 token 无限的世界里，你也得知道何时停手、接受哪些 trade-off。Agents 会毫不犹豫地一直钻下去。」
  • @adityaag（179 赞）：「我很会写软件」正在变成更弱的优势，他给了三条路——去做正在吞掉软件的那件事（AI 研究、基础设施、工具）；找一个世界级领域专家搭伙；或者只是用一堆 agent 交付同样的 backlog。他明确说第三条最不吸引人：「如果你的野心只是更快地清空同一个 backlog，你在浪费这个时代。」
  • @_catwu（246 赞）：她最喜欢的 PM 用法是让 Claude 回答「上周谁用得最多？把 top 10 做成 artifact，然后逐个约 15 分钟聊一下」——最快的用户反馈回路。
  • @zarazhangrui（139 赞）：「记住写代码是手段，不是目的。目的比手段重要。」
  • @petergyang（6 赞但值得存）：任何你交付的东西现在都可能被 AI 反编译重建，没有专有数据、分发或其它壁垒的软件将很难赚钱；传统 SaaS 尤其脆弱——它贵，而且塞满了「为人设计、agent 根本不需要」的功能。

7）播客：Every 为什么从「人人一个 agent」转向「一个公司 agent」

本期唯一一档：AI & I by Every（10 月 7 日，Dan Shipper 对话 Every 平台负责人 Willie Williams，《Why Every Traded Personal Agents for One Company Agent》，带完整转写）。要点：

  • 边界正在固化：专业侧倾向「一个组织一个 agent」——它随工作流学习、靠全员日常使用变强；个人 agent「没有这里的上下文，很难教，需要在这儿待满一年才追得上」。他也明确不认为行业会重演「每个员工各带一个 agent、公司规模翻倍」的混乱。
  • 个人侧的拉力巨大：以前阻碍个人 agent 的是安全与运维（自托管、怎么管），现在大玩家带着资本进来，消费级体验会迅速变好；因此会出现「上班用公司 agent、回家用个人 agent」的分裂。
  • 主动性在加码：Instinct、Muse 这类产品开始主动触达用户。他的判断是，当 AI 主动找你时，「一个有人格名字的 agent」能让你立刻定位上下文——游泳池教练发消息，你一秒就知道该看什么。这解释了人格化产品为什么在「主动」这一维度上更有意义。
  • feed 化世界：他把 Slack、邮件、客户报告收进自己搭的解析 feed，用 AI 把数据源转成「需要你决策的事 / 仅供参考的事」的信息流；他的判断是「以前做 feed 需要几亿用户的大公司，现在每个人都能有自己的 feed」。
  • 工程管理反而最没变：他认为相比其它岗位，EM 恰恰是最像过去的一个——杠杆仍然来自「你能看到多大的战场」，只是收集信息这一步被 agent 替代了。

七、其它信号

  • @joshwoodward（Google Labs / Gemini） 92 赞：「Mask-based editing is my favorite from today, much more coming soon」——mask 式局部编辑成为他当天最爱的功能，更多在路上。
  • @rauchg（Vercel CEO） 164 赞：「Thinking fast and s̶l̶o̶w̶ a bit less fast under a confidence threshold」——把「快慢思考」做成一个按置信度触发的简单功能，他认为对大规模的 AI 决策会非常有用。
  • @steipete（Peter Steinberger，OpenClaw / OpenAI） 82 赞：把团队 claw 接到 X 上触发工作，未分配的 session 谁都能领，agent 会自己查「相关代码最近由谁改过」然后在服务器上 ping 人；整个东西是「一个 prompt」写出来的——因为插件现在支持热重载，团队服务器自己把自己扩展了。
  • @swyx（Latent Space） 19 赞 发了一条值得记的提问：「what is your default/workhorse coding agent today, Oct 2026?」——日常工作马的分化，比模型排行榜更能反映真实格局。
  • @thenanyu（Nan Yu，Codex 产品） 25 赞 的担心值得存档：AI 的介入会让那些「没人愿意维护、但总得有人维护」的系统严重退化。这是今天所有「AI 全面改写软件」叙事里最该被引用的反方意见。
  • @garrytan（YC） 用「再三个 prompt」把某段实时渲染从勉强跑动推到 640x480 / 35fps、每帧吃 8 个 CPU 核心——当娱乐看也说明一件事：性能调优的门槛正在被提示词吃掉。

八、今日小结

  • 产品机制：把交付节奏写成带惩罚条款的公开合约（Codex 的 28 天实验），大概是今天最值得抄的一条「发布方法」。
  • 架构方向：Claude Code 给出的图景是「云端大脑 + 本地双手」，难点在状态同步与权限；Anthropic 的战略重心是把 agent runtime 嵌进别人的协作界面，而不是自己做一个界面。
  • 经济账：播客里那句「后训练赢推理」配上一个可执行动作——把钱先花在最大规模的工作负载上做后训练，并在训练阶段就把 token 效率当成推理账单的一部分去优化。
  • 风险面：反编译让软件护城河变薄，agent 上量让安全从「代码审计」扩展到「权限与工具链」，两条线的交汇处就是下一批产品的起点。
  • 补充窗口的三条增量：小模型（Haiku 5.5）在「更快 + 便宜 75% + alignment 更好」三个维度同时前进；Sonnet 5.5 把缓存读压到 $0.10 / 百万 token，长时程 agent 的成本结构又降了一层；OpenAI 一边让 ChatGPT 生成自定义 UI，一边用 Dots 把「持久 + 主动」的个人 agent 推到第二周。
  • 同一团队的两套发布策略：Codex 上周用 28 天公开合约立规矩，这周静默重发 codex cloud；「何时公开承诺、何时静默交付」本身成了产品决策。
  • 什么时候停手：Rauch 那句提醒值得贴在显示器上——即使 token 无限，注意力、时间、机会仍然稀缺，agent 会一直钻下去，停手的判断只能由人来做。
  • 怎么写代码这件事反而变保守了：可以用 AI，但要能解释；练系统设计，而不是练语法。
