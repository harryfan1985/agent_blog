Agent 记忆的真相：0 次主动使用，139 次自动交付

July 26, 2026

一个叫 Swapnanil Saha 的独立研究者发了一篇论文，说了一个让整个 agent memory 领域难堪的事实：你给 agent 最好的 memory 工具，预填好最有用的知识，它一次都不会用——0 次。114 轮对话，零。而当你把这些知识从 agent 的工具箱里拿出来，塞进 harness 的控制回路里，让它自动在正确的时间出现在 agent 眼前，它每次都到——139 次 compaction 恢复，一次不落。

这不是工具好坏的问题。这是 delivery channel 的本质区别。论文把这两个通道命名为 Content Plane（内容平面）和 Control Plane（控制平面），论证了后者的可靠性是 100%，前者的可靠性约等于 0。

问题：你的 Agent 为什么不查 Memory？

如果你用过 coding agent，你可能写过 CLAUDE.md，也可能用过 agent 的 memory 功能。Saha 的实验告诉你一个残酷的事实：

实验条件Memory 使用次数Turns
无 memory（Arm A）—106.3 (mean)
有 store + 工具 + 冷启动（B+C）0–177.0
有 store + 工具 + 预填充了任务相关知识（V）0114
同样预填充的 store，harness 自动注入（H）多次（注入后主动 expand）95

最打脸的是 Arm V：同一个 agent，同一个任务，store 里预填了四个与任务直接相关的笔记（包含一个 gotcha 锚定在 guard site 所在文件），工具已连接，workspace instruction files 里 32 次提到 "使用 memory"——零次 memory 调用。

这不是模型智商问题。Saha 引用 TriggerBench（arXiv:2606.23459）和 MEMTRACK（arXiv:2510.01353）证明：prospective memory（看到一个 cue 然后想起"这事我得做"）比 retrospective memory（"你知道 X 吗？"→"知道"）难得多，且随上下文长度衰减——恰好是 long-running agent 最需要的那种 memory。厂商早就知道这一点：Anthropic 的 memory tool 在所有 prompt 里强制插入 all-caps 指令 "先检查 memory"；ChatGPT 的 memory 做自动捕获和自动注入，连 voluntary lookup 工具都没有。

两层记忆理论

Saha 提出的模型很简洁：

Tier 1 — 文档Tier 2 — 脑记忆
内容specs, ADRs, runbooks（去上下文，持久化）gotchas, locations, tacit fluency（情境绑定）
编码有意图的作者行为工作的自动副作用
检索主动 lookupCue-driven，大程度上不自觉
失败模式过时；write-only archivesContext window reset 时丢失
现有支持✓ CLAUDE.md 等✗ 不存在

每一层对应不同的认知机制，这些机制又驱动了具体的架构需求。例如：编码是 incidental 的（你不刻意去记也记住了）→ capture 不能依赖 agent 主动保存；检索是 cue-driven 的（看到某段代码才想起来"等等这有个坑"）→ 默认交付通道应该是注入，voluntary lookup 是 fallback。

最关键的理论支柱来自 Clark & Chalmers (1998) 的 extended mind 标准：一个外部 store 要算作 "mind" 需要三个条件——可靠可用、近零努力、自动认可（endorsement）。Injection 满足全部三个；voluntary lookup 一个都不满足。

五个维度的触发词汇

论文提出每条 memory 携带触发条件，触发词汇覆盖五个维度：

维度触发器例子
path被触碰文件匹配 glob"当你碰 src/config/*.yaml 时提醒我这个配置是 load-bearing"
symbol代码实体被引用（需要 code symbol graph）"调用 Resequencer.process() 时注入反向顺序 gotcha"
semantic当前活动相似度 ≥ floor"你现在做的和上次的 migration 问题很像"
eventsession start / prompt submit / pre-edit / pre-compaction"每次 compaction 后重新注入 directives"
temporalnot-before / cooldown"24 小时内不要重复提醒"

这五个维度可以组合：path AND semantic（"当你在碰那个文件且语义类似上次"），或 event OR temporal（"每次 session start 或 48 小时后"）。评估是确定性的（harness-side），不走模型判断。论文说：没有 surveyed 系统组合了这些属性。尤其 symbol-conditioned memory 需要一个 code symbol graph，现有系统（MemGPT/Mem0/Zep/A-MEM/PROJECTMEM）一个都没有。

Harness 自动注入 vs Agent 主动查询：实测对比

Saha 在两条独立的通道上验证了确定性交付：

通道机制结果
API ProxyHTTP proxy 在 model-API 路径上确定性注入262 requests：5 injected, 236 skipped, 0 误报
Native HooksLifecycle hooks (session start / prompt submit / pre-tool-use / pre-compaction) → hook binary → daemongotcha 在 agent 首次触碰锚定文件时精准触发（~20s / ~7min），0 误报（40/35 evaluations）

注入不仅不犯错，还激活了 agent 的主动性：Arm H 的 agent 在注入后秒级内展开了所有三个注入条目（通过 id recall），后来还做了 semantic recall + 淘汰了过时的 gotcha。注入产生 engagement，不是取代它。

衰减探针：当 Compaction 吃掉你的记忆

这是论文最震撼的部分。Saha 设计了一个残酷的实验：

  • 10 个合成操作事实，在 phase 0 一次性呈现后删除源文件（堵死 re-read）
  • 一个 64 文件审计任务，compaction window 固定在 100K tokens
  • 用 Haiku 4.5（最便宜最快的模型）跑——只为让 k 足够大
  • Arm N：无 memory tier。Arm M：10 个事实作为 one-line notes 预填在 working-memory store 里，通过 hooks 每次 compact-resume 重注入

结果令人震惊：

指标Arm N (无 memory)Arm M (注入 store)
Compaction 次数 k108138
首 summary 携带 10/10 事实0/100/10
106/108 summaries 0/10✓—
后 72 连续 summaries 0/10—✓（注入仍在继续）
Fact-bearing deliveries0139（每次 compact-resume + 首发）
终点得分10/10 — 无效10/10 — 干净

三个关键发现：

  1. Summary channel 在第一个 boundary 就全丢了。两个 arm 的 summary 1 都是 0/10。Summary 的选择不可靠，与事实在 context 中是否存在无关——Arm M 的 context 明明在 compact 前有这些事实，summarizer 还是丢了。
  2. Agent 被剥夺 memory tier 时会手建一个。Arm N 的 agent 在闭合阶段做了 260 个 shell commands，其中 38 个是 fact archaeology——grep 自己的 session JSONL 和 harness 的 persisted tool-result files。它在从 harness 的磁盘持久层重建 episodic memory。这是最诗意的发现：agent 在缺少 sanctioned memory 时，会违反操作禁令，自己去 grep 它不应该碰的东西。最终它确实找到了所有 10 个事实——但这是 unintended + expensive 的方式。
  3. Continuation summaries 会传播错误。Arm M 的 summaries 传播了 agent 自己编造的 "Phase 52: Files 203–206"（在 16-phase 64-file audit 中）。Summaries 巩固模型的当前信念，不验证它们。

Why This Matters

这篇论文对 agent memory 领域的冲击是地基级别的：

  1. Voluntary memory = 0 是实证，不是假设。整个 agent memory 文献的默认前提——"给 agent 记忆工具，agent 会用"——被实验推翻。这是 feature 层面的 mismatch，不是 bug。
  2. Content vs Control 框架是范式贡献。不是 "memory 应该更好" 的 incremental improvement。它重新定义了问题的归属：memory 不是一个存储问题（存什么、怎么检索），而是一个控制平面的交付问题（什么、何时、进入 context 的方式）。
  3. Delivery, not storage, is the product.同一个知识，voluntary lookup 让它像参考文档，deterministic injection 让它像记忆。相同的 content，不同的 delivery channel = 不同的认知角色。
  4. Harness 会抵抗 memory-carrying 配置。衰减探针的 thrash guard 把 Arm M 的 read cap 从 8K 降到 6K——harness 把 memory 注入的固定开销识别为 refill pressure。为 memoryless 操作调优过的 harness 会主动对抗试图携带 memory 的配置。

局限

  • n 极小：12 graded runs，每个 decay arm 仅 1 个 gated run。方向性证据，不是效应量估计。
  • Capture 半侧未评估：衰减探针的 10 个事实是 harness seeded 的，agent 自主捕获 memory 的能力未验证。
  • 单代码库、单任务、单 agent 产品、单模型家族：Claude Sonnet 5 + Haiku 4.5，Apache Camel。
  • 五维触发只实测了三维（path, event, semantic）。Symbol 和 temporal triggers 已实现但无 graded run 实测。
  • Haiku 是特异性选择：用最小最快的模型让 k ≥ 100 feasible。更大 summarizer 的衰减行为可能不同。
