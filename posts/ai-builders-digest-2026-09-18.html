AI Builders 日报 · 2026-09-18

September 18, 2026

今天的 builders 时间线被 Anthropic 刷屏：Claude Code 的全新 Projects 体验开始滚动推送——一个项目一个 Agent，会话不再是你要管理的对象。此外，Google Labs 把 AI Agent 塞进了家庭生活，Vercel 披露了部署量的井喷曲线，而 Aaron Levie 断言：Agent 已经占掉了世界上大部分推理 tokens。

本日核心：Agent 产品的形态正在从「会话」走向「项目」——有记忆、有子代理、有调度，24/7 在后台替你干活。软件生产端则在见证历史：明年的新增软件量可能超过计算机史上全部产出的总和。

一、Claude Code 新 Projects：一个项目一个 Agent（今日主菜）

Anthropic 公布了 Claude Code 的全新 Projects 体验，几位核心成员今天集体发声：

  • Boris Cherny（Claude Code 创造者）：「Projects 不只改变了我与 Claude 的交互方式，还改变了我写代码的方式。我不再管理会话——想法来了就发出去，Claude 自动把它们拆成线程，项目会记住我的工作习惯。我现在大量的编码都在这里完成。」原文（2.3k 赞）；另一条里他确认新体验正在滚动推送。原文（1.9k 赞）
  • Cat Wu（Claude Code + Cowork）：新体验里 Claude 协调你的所有会话——批量派发一组任务后就可以走人，随时能拿到聚合的状态更新；长期记忆会随使用不断进化，让人在一个更高的抽象层级上工作。未来几周滚动推送。原文
  • Thariq（Claude Code）：Projects 把 Claude Tag 的架构带进了 Claude Code——每个项目一个 Agent，负责管理记忆、按任务派生 subagent，还可以要求它主动干活、定时执行。「比一堆散落的会话舒服多了。」原文（1k+ 赞）
  • @claudeai 官方补充：线程跑在云端，电脑离线也在继续干活（暂时无法访问本地文件与内网工具，本地支持「很快」到来）；项目随时间成长——每个线程都读写共享记忆，能记住「发版挪到了周五」「动 billing 服务前先问谁」，library 保存你上传的和 Claude 创建的文件；现有 Pro/Max 项目的用法不变，可加入 waitlist 提前体验。原文① 原文② 原文③

一句话总结：从「会话」到「项目」，Agent 从你开一次聊一次的工具，变成常驻、有状态、可调度的同事。

二、OpenAI 这边：让两个 Agent 就「完美 styleguide」达成一致

OpenAI Codex 团队的 Thibault Sottiaux 抛出了今日互动量最高的一条（5.5k 赞、1800+ 回复）：有没有人试过让 Astra 和 Fable 就完美 styleguide 达成一致，然后用 Web MCP 把它托管起来？让多个 Agent 在共享规范上互相拉扯再收敛——多 Agent 共识与工程规范的沉淀，社区显然对此很有共鸣。原文

三、Google Labs 发布家庭版 CC：Agent 管家务

Google Labs 宣布全新 CC——一个为家庭打造的 AI Agent：最多添加 5 位家庭成员；每天早上发「Your Day Ahead」简报邮件；自动同步共享 Google Calendar 和 Tasks；在 Google Chat 里协调事务（周餐计划、开学采购清单）；在你的指示下代办文书（家长同意书、各类表格）；还能记住哪些信息是「全家通用」（常去的餐厅）、哪些是「个人专属」（饮食限制、时区）。美国区 18+ 可加入 waitlist。原文（539 赞）

四、软件生产井喷：Vercel 十个月新增 14 亿次部署

Vercel CEO Guillermo Rauch 给出一组惊人数字：Vercel 花了 10 年达到 10 亿次部署，而最近 10 个月又增加了 14 亿次。「明年生产的软件，很可能超过计算机历史上所有软件的总和。」其中很多会是微小、个人化甚至一次性的软件——一个带 JS 的 HTML 文件、一份报告、一个定价计算器、一套幻灯片，直到复杂的应用、Agent 与平台。部署速度是 Vercel 的执念：从部署、上传、分配域名到全球生效，被压到了 1 秒以内（同时不牺牲 CDN、防火墙、不可变部署与回滚）。原文（508 赞）

五、行业观察：Agent 正在吃掉全世界的 tokens

  • Aaron Levie（Box CEO）：Agent 已经构成推理量的大头，未来一两年将趋近全部。世界的 tokens 消耗将主要来自 7×24 小时在后台执行任务的 Agent：审查所有代码变更来保障软件安全、在工作流里处理数据、承担招聘与客户开发中的大部分调研、盯住每一个系统的事件流和日志……他本人过去一周就上了好几个「一个月前技术上还不可能」的新工作流。原文
  • Amjad Masad（Replit CEO）：在转发基建讨论时表态——「这就是为什么我们需要海量的数据中心（值得）」。算力需求的膨胀不是泡沫，是 Agent 时代的水到渠成。原文

六、自治 Agent 实践两则

  • Nikunj Kothari（FPV Ventures）：做了一个「自驾公司」（self-driving company）实验 nosugarforkids.com——一个只收录健康儿童零食的目录站。一个 Claude Agent 每天醒来：检查目录新品、清理死掉的商品、找能扩大触达的选题、查 dataforSEO 和 Search Console 表现、写稿改稿、控制质量避免 slop，甚至开始联系媒体要外链。零外链、零社媒起步，自然增长到每天约 6000 次展示、60 次点击。他还给站点配了完整的 MCP / WebMCP，可以直接把自己的 Agent 指向它。原文 MCP 补充
  • Garry Tan（YC CEO）：点赞 Memorable 的思路——用 embeddings 而不是堆更多 tokens 来做记忆优化，「这是一种强大的新记忆路径」。在上下文工程火热的当下，值得记一笔。原文（477 赞）

结语

今天的关键词是「从会话到项目」：Claude Code 的 Projects、Google Labs 的家庭 CC、Nikunj 的自驾网站，都在把 Agent 从一次性对话工具变成有记忆、有日程、有产出物的常驻系统。如果你的工作流还停留在「开个新会话」的层面，今天值得重新设计一遍——把上下文交给项目，把调度交给 Agent，把注意力留给真正的判断。
