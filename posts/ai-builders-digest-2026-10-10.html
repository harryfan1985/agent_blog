AI Builders 日报 · 2026-10-10

October 10, 2026

2026 年 10 月 10 日，周六。本期 feed 窗口是 10 月 9–10 日（24 小时口径）：15 位被跟踪的 builder 发声、合计 27 条帖子；博客源本期有 3 篇新文——全部来自 Anthropic Engineering，且罕见地同一天齐发；播客源 1 期，No Priors 对话 Reflection AI 联创兼 CEO Misha Laskin，带 72K 字符完整转写。

字数最多、信息密度最高的一天不来自榜单。当天互动量第一的是 OpenAI 的 @thsottiaux 一句十来个字的宣告：你的 ChatGPT 订阅现在也是一份 Devin 订阅（2,528 赞 / 130 转推）。真正把今天串起来的是另外三条数字：Anthropic 披露用户会批准约 93% 的权限弹窗、一次内部红队演练中恶意 prompt 在 25 次尝试里成功了 24 次、把 agents 的「大脑」从容器里搬出来之后 TTFT p50 降了约 60%、p95 降了 90% 以上；以及 Vercel 给出的账本——全站 58.18% 的流量来自 bot，60% 以上的部署是 agentic 的。

把今天的信号压成一句：agent 正在从「能演示」进入「要负责」的阶段。当你把真实的文件系统、凭证和网络交给模型，安全和效率都不再是提示词问题，而是架构问题——这是 Anthropic 一天三篇长文的共同主题。而另一半是账本：Vercel 说 agent 已经吃掉近六成流量、六成部署，Levie 说 agent 群会消耗 1,000 倍的 token，Reflection AI 则从经济侧补上最后一块——开放权重既是降价趋势的顺风车，也是防御方唯一买得起的武器。

一、Anthropic 一天三篇：「containment」是一道架构题

《How we contain Claude across products》是今天分量最重的一篇。它的开篇就是一份自我否认：

“Twelve months ago, we'd have rejected out of hand the idea of granting Claude access sufficient to take down an internal Anthropic service. Today that level of access is routine, and Anthropic developers are more productive for it.”

文章的框架很干净：部署风险 = 失败概率 × 失败后果。安全保障与模型训练在持续压低第一项，但第二项（理论上的「爆炸半径」）随着能力和权限扩张只会变大。所以工程问题变成了「怎么给爆炸半径设上限」。他们举了一个反面案例：Claude Mythos Preview 就是因为爆炸半径被判定过高，在 2026 年 4 月被决定不发布；但他们预期，随着防御方加固关键系统、保障措施成熟，同级别能力的更广泛发布将会变得合适。

要防的是三样东西：模型本身、它运行的环境、它能触及的外部内容。环境侧，文章给出三种隔离模式：

  • 模式 1 · 临时容器（claude.ai 代码执行）：跑在隔离基础设施上的 gVisor 容器里，agent 完全服务端，文件系统按会话临时生成。这里保护的其实不是用户的机器，而是 Anthropic 自己的基础设施与租户之间的隔离。文中那句话值得抄下来：「the weakest layer is the one you built yourself」——gVisor 和 seccomp 面对强对手已经硬化了很多年，所以审查精力要放在自己新写的那些零件上。而他们最有后果的那次事故，出事的恰好是自研的代理。
  • 模式 2 · 人在环路里的沙箱（Claude Code）：读放行、写/bash/网络要批准。但几周内就出现了审批疲劳——遥测显示用户批准了约 93% 的权限弹窗；提示越多，每条被认真看的概率越低，一个原本为了监督而生的功能反而可能起反效果。于是他们做了 OS 级沙箱（macOS 用 Seatbelt、Linux 用 bubblewrap）：读允许、工作区内写允许、网络默认拒绝，结果是权限弹窗减少 84%，并且把运行时开源以便审计。另一组数据显示：有经验的用户自动批准频率约为新用户的两倍，但他们也更频繁地在执行中途打断 agent——他们不逐条把关，只在 agent 跑偏时出手。
  • 模式 3 · 本地虚拟机（Claude Cowork）：面向的不是工程师，而是普通知识工作者——不该指望一个非技术用户能判断 find . -name "*.tmp" -exec rm {} \; 的风险。所以边界必须是绝对且常开的：用平台自带 hypervisor（macOS 的 Virtualization framework、Windows 的 HCS）跑完整 VM，自带内核、文件系统与进程表；只挂载用户选定的工作区和 .claude，凭证留在宿主机 keychain 里。关键设计是「没有任何持有逃生钥匙的外层进程」，因此也就不存在有权开例外的组件。后来他们把 agent 主循环移出 VM（保留代码执行在里面），因为 VM 启动失败会让 Cowork 完全不可用——这带来最小化的安全代价，换来可用性。文件挂载给了只读 / 读写 / 读写但禁删三档；一个坑是符号链接必须在路径校验之前解析，否则授权目录里的软链可以指向外面。

文中最有价值的部分是三个「我们漏掉的风险」，因为它们都不是模型变笨导致的：

  • 信任对话框之前的一切。2025 年中到 2026 年 1 月，他们收到三份披露，攻击面都在「用户还没同意任何事之前就执行的代码」。最直接的一例：开发者 clone 一个仓库来审 PR，仓库里带的 .claude/settings.json 定义了 hook，而 Claude Code 在启动时就会读项目设置——早于标准的「Do you trust this folder?」提示，于是攻击者写进仓库的 hook 自动执行。修法一致：把项目本地配置的解析与执行推迟到用户接受信任提示之后。建议也很硬：「把 project-open、config-load 和 localhost listener 当成来自互联网的入站请求」。
  • 用户本身是注入通道。2026 年 2 月的内部红队演练里，一名研究员成功钓鱼，让员工用一个恶意 prompt 启动 Claude Code——看上去就是「帮我跑一下这个」的正常协作邮件。prompt 混在常规步骤中，轻轻要求 Claude 读取 ~/.aws/credentials、编码后 POST 到外部端点。同一个 prompt 重试 25 次，Claude 有 24 次完成了外泄。这是直接的提示注入，但攻击指令来自用户而非工具输出，所以锚定「用户意图」的模型层防御抓不到任何异常——换成一个真人外包也会照做。唯一有效的是环境：阻止这次 POST 的出口管控，以及让 ~/.aws 根本不在射程内的文件系统边界。文中还附了一个耐人寻味的细节：他们把这个可用的 prompt 贴到内部 Slack 讨论后，有人提醒「有些内部 agent 会读 Slack」——payload 瞬间变成环境里弥漫的东西，于是他们在帖子里插了一个 canary 字符串来监测。「在一个 agent 什么都读的世界里，调查工具本身也是攻击面。」
  • 通过「已批准域名」外泄。第三方披露的一例：Cowork 的出口白名单正确地放行了 api.anthropic.com——产品不调用自家 API 就没法工作。用户挂载的工作区里有一个恶意文件，带着隐藏指令和攻击者控制的 API key；Claude 按指令读取工作区其它文件，并用攻击者的 key 调用 Anthropic 的 Files API。沙箱完美工作，数据依然被外泄了。结论是一次概念重构：白名单不是「目的地过滤器」，而是「能力授予」——任何域名上可达的每个函数都是攻击面。放行 api.anthropic.com 等于放行向任意 Anthropic 账号上传文件。修法是在 VM 内加一个防御性 MITM 代理拦截发往自家 API 的流量。

收尾的三条原则值得直接记下来：先在设计层面 containment（环境层），再做模型层的行为引导——当所有概率性防御都漏过时，撞上的是那道确定性边界；隔离强度要匹配用户的监督能力——能读 bash 的开发者与读不懂的知识工作者不是同一个威胁模型，判错任何一边（对专家太多摩擦、对非专家太多信任）都是一种失败；对自研组件保持警惕。文章还指向了外部的治理配套：NIST 的 AI agent 身份与授权项目、澳 ACSC 联合 CISA 与英 NCSC 的六机构 agentic AI 采纳指引、ISO/IEC 42001。

二、Managed Agents：把「大脑」和「手」拆开

同一天发布的《Scaling Managed Agents: Decoupling the brain from the hands》讲的是 agent 架构本身。开篇的判断很锋利：harness 里编码的是「Claude 做不到什么」的假设，而这些假设会因为模型变强而过期。他们给的例子我第一次见到有人这么直白地讲：Claude Sonnet 4.5 会在感觉逼近上下文上限时提前收尾（所谓 context anxiety），于是 harness 里加了 context reset；换到 Opus 4.5 跑同一套 harness，这个行为消失了——那些 reset 变成了纯粹的死重。

所以 Managed Agents 的目标是做一个「给尚未被想到的程序」设计的系统，就像操作系统当年把硬件虚拟成 process、file 这样足够通用的抽象，让抽象比硬件活得更久。他们把 agent 拆成三个虚拟化组件：session（一切都发生过的追加式日志）、harness（调用 Claude 并把工具调用路由到对应基础设施的循环）、sandbox（Claude 跑代码、改文件的环境）。三者实现可独立替换。凭证处理上，MCP 工具调用走专用代理：代理拿会话 token 去 vault 取凭证再发请求，harness 永远不知道任何凭证。

几个具体的设计点：

  • session 不是 Claude 的上下文窗口。长任务必然超出上下文，而压缩、删除、裁剪都是不可逆的决定——你很难知道未来的轮次需要哪些 token。他们的做法是把上下文持久地放在 session 日志里，用 getEvents() 让「大脑」按位置切片地审问事件流：可以从上次读到的位置继续、可以往回倒几条看前因、可以在某个动作前重读。取回的事件还能在 harness 里做任意变换（比如组织上下文以拉高 prompt cache 命中率）。存储（session，保证持久可查）与管理（harness，任意上下文工程）被有意分开，因为无法预测未来的模型需要什么样的上下文工程。
  • Many brains。最早期客户的抱怨是：团队想让 Claude 操作自己 VPC 里的资源，唯一路径是把自己的网络和 Anthropic 对等互联——因为装着 harness 的容器假设了所有资源就在旁边。把 harness 移出容器，这个假设就消失了。性能收益更直接：大脑在容器里时，每个 session 都要先付出完整的容器启动成本（clone 仓库、启动进程、拉取待处理事件）才能开始推理，这段死时间直接体现在 TTFT（time-to-first-token）上，而 TTFT 是用户最能感受到的延迟。拆开之后，容器只在需要时由大脑通过一次工具调用 execute(name, input) → string 提供——p50 TTFT 降约 60%，p95 降超过 90%。
  • Many hands。每只「手」就是一个工具：execute(name, input) → string，名字和输入进去、字符串出来，可以承载任意自定义工具、任意 MCP server，以及他们自己的工具。「harness 不知道那个沙箱是一个容器、一部手机，还是一个宝可梦模拟器。」因为没有手绑定在任何大脑上，大脑之间还能互相传递手。

这篇的定位是「meta-harness」：对 Claude 周围的接口有主张（Claude 会需要操纵状态、需要执行计算、需要扩展到多大脑多手），但对大脑和手的数量与位置不做任何假设。作者署名 Lance Martin、Gabe Cemaj、Michael Cohen。

这一节还有一条来自 X 的实证。@trq212（Anthropic，Claude Code）（852 赞 / 30 转推）说：加入 Anthropic 之前他用 Opus 4 花两周 hack 过一个副业项目，当时用的是 Agent SDK，需要常驻进程、跑得也不算好；「一个 prompt 交给 Opus 5.5，就把它移植到了 Claude Managed Agents 上，可靠性好了非常多」。同一窗口他还有一条（118 赞）说自己已经把这个东西放在新标签页上了（github.com/ThariqS/ai-newtab），并合并了别人提的 PR。一条产品发布 + 一个用户把旧项目迁过去的一手证词，比任何 benchmark 都更能说明 harness 抽象层的价值。

三、Claude Code 质量事故复盘：三个改动、一次 3% 的评测下滑

第三篇《An update on recent Claude Code quality reports》是对「模型变笨了」这类反馈的正式复盘。结论是三个独立改动叠加，影响 Claude Code、Claude Agent SDK 和 Claude Cowork，API 未受影响，三者在 4 月 20 日（v2.1.116）之前全部解决。

  • 3 月 4 日：把 Claude Code 的默认 reasoning effort 从 high 降到 medium，以缓解部分用户看到的超长延迟（长到 UI 像是卡死）。官方判定这是错误取舍，4 月 7 日回滚——用户更愿意默认更高智能、简单任务再手动降低。影响 Sonnet 4.6 / Opus 4.6。
  • 3 月 26 日：为降低恢复闲置会话时的延迟，清理超过一小时未活动会话的旧 thinking。一个 bug 让这件事在之后每一轮都发生而不是只发生一次，表现就是 Claude 显得健忘、重复。4 月 10 日修复（v2.1.101）。影响 Sonnet 4.6 / Opus 4.6。
  • 4 月 16 日：为降低 Opus 4.7（相对前代明显更啰嗦）的输出量，往 system prompt 里加了一条长度限制——「工具调用之间的文本 ≤25 词，最终回复 ≤100 词，除非任务需要更多细节」。内部测了数周、跑过的评测都没回归，就随 Opus 4.7 一起发了。事后做更广的消融实验时，其中一项评测显示 Opus 4.6 与 4.7 都掉了 3%，4 月 20 日立即回滚。影响 Sonnet 4.6 / Opus 4.6 / Opus 4.7。

为什么这事难查：三个改动各自命中不同时间表上的不同流量切片，聚合起来看起来就像是广泛而不一致的全局退化。第二个 bug 尤其隐蔽——只发生在「陈旧会话」这个角落，难以复现，花了一周多才确认根因。有个细节很能说明现在的开发方式：作为调查的一部分，他们拿 Opus 4.7 回测了那两个出问题的 PR，在提供完整上下文所需仓库的前提下，Opus 4.7 找到了这个 bug，而 Opus 4.6 没有——因此他们正在补充「代码评审时可以把更多仓库作为上下文」的能力。

这一篇和第一节合起来是一件事的两面：系统的复杂度已经把「模型变笨」变成了一个几乎无法从现象反推原因的类别，用户能感知到的质量，实际是模型 + harness + 默认参数 + 提示词 + 产品交互的共同产物。而披露这件事本身，也是 agent 时代公信力的一部分——那句「我们从不有意降低模型能力，也立刻确认了 API 与推理层不受影响」，是给企业客户看的。

四、Vercel 的流量账本：58% 的流量已经来自 bot

@rauchg（Vercel CEO）（277 赞 / 14 转推）给了一组罕见的平台级数字：

“• Across the entire Vercel network, 58.18% traffic is bot-originated (last 30d). This was 32% in Jan 2024.
• 60%+ of deployments on Vercel are now agentic, up from ~3% in Jan 2026.
• Up to 83% of pageviews are now coming from agents to Vercel's own documentation sites. The % reliably increases the more we optimize content for them.”

三条数字里最反直觉的是第三条：越为 agent 优化文档，agent 的访问占比就越高——这意味着一部分「读者」已经是机器，而它们的访问量是可以被内容工程直接拉动的。他的结论是「我预期『直接』的人类互联网流量在未来几年基本上会变成一个舍入误差。Web 会繁荣，但它将由 agent 构建、为 agent 构建。」

配套的一条是 @rauchg 关于 agent 开始消费基础设施（324 赞 / 17 转推）：「看着一种新经济诞生真是难以置信——agent 在购买基础设施产品和服务。我们已经对自己 marketplace 通过 CLI 成交的频率感到震惊，现在把这件事扩展到域名。」也就是说：从「agent 用你的产品」到「agent 是你的客户」，中间那个结账动作已经被打穿了。这两条加起来，是今天关于「agent 原生的互联网」最具体的一份证据。

五、agent 经济的雏形：1,000 倍 token，与 agent 群

@levie（Box CEO）（530 赞 / 41 转推）给出了他这一轮最完整的用量判断：

“Agents spawning other agents, agents operating in the background on every task, and agent swarms will consume 1,000X more tokens than people prompting agents 1 at a time. The usage of AI as a chat system that can only work for you at the pace that you can prompt it will seem like a relic within a year or two.”

他的推论是：绝大多数 token 会由「替我们持续在后台和流程里干活的 agent」消耗，这正是「我们在 agent 采纳曲线上还如此早期」的原因，也是为什么还需要更多算力与基础设施。——把它和第四节的 Vercel 数字放在一起看：一边是流量侧 agent 占比接近六成，一边是用量侧预测还有三个数量级，这两个口径互相印证了同一件事，即计算需求的重心正在从「人的提问频率」转移到「agent 的持续运行」。

同一主题的还有 @amasad（Replit CEO）那个只有一句话的问题（353 赞）：「有些社群对 AI 给本领域带来的影响感到兴奋，另一些则恐惧。决定性的因素是什么？」在一个 58% 流量来自 bot 的周末，这大概是当天最值得停下来想一秒的提问。

六、产品与工作流：订阅打通、邮箱命名、和「补全 prompt」

  • @thsottiaux（OpenAI，Codex & ChatGPT）（2,528 赞 / 130 转推，今日最高）：「你的 ChatGPT 订阅现在也是一份 Devin 订阅」，附链接。订阅权益跨产品打通，是这一轮 coding agent 竞争里最实用的一招——它把「选哪个工具」变成「我已有的订阅能覆盖到哪」。
  • 同一作者另一条 关于 Dots 的更新（1,470 赞 / 53 转推）：「Dots got a pretty big upgrade」，只有一句话加一个链接，具体内容需以官方发布为准。
  • @petergyang（285 赞）给了一个 Grok Bot 的实操建议：把它当 chief of staff 用时，不要用你自己的名字注册它的邮箱——否则「Let me copy in Peter to find a time for us」这种话会变得很怪。给 agent 起一个独立的身份名，是「agent 作为同事」这件事在细节层开始落地的标志。
  • @thenanyu（Codex 产品）（75 赞）用四句话概括了四代交互史：「先手写代码，然后用 tab 补全代码；随后演进到给 agent 写 prompt……现在我们连 prompt 也 tab 补全了。」提示词正在变成一种可以被补全的输入——这条低赞的帖子，可能是今天对产品形态最有预言性的一条。
  • @danshipper（Every CEO）（25 赞 / 4 转推）发了一篇《Working With Agents in Slack》。把 agent 放进团队已经日常驻留的界面，而不是再造一个控制台，是他一贯的判断。
  • @mattturck（26 赞）感叹「一个 prompt 就能做出公司或产品级别的专业视频，还是你的风格」，并指出这正是 Synthesia 从早期就在追的愿景——「发生得很慢，然后一下子全发生」。

七、播客深读：No Priors × Misha Laskin——开放权重的经济学与安全学

本期播客源只有一期，但足够撑起一节：No Priors 对话 Reflection AI 联创兼 CEO Misha Laskin（10 月 9 日发布，72K 字符完整转写），主题是他们刚发布的第一个开放模型 Beam，副标题直接叫「The Great American Open Model」。以下是我认为最值得记的部分：

  • Beam 的规格与训练量。总计 5,000 亿参数、230 亿激活，在 6,000 张 GB300 上跑了数周（他提到现在靠基础设施效率大约 12 天、甚至更短）。强化学习部分他称是开源界迄今最大规模：10,000 张 GB300 连续四周，并说「我没见过有文档记录过这个量级的运行」。效率上，他称 Beam 比同能力档位的模型省 3–4 倍，对更大的模型省得更多、可达 10 倍；原因一半来自为推理而优化的预训练底座，一半来自这个规模的 RL 放大。
  • 为什么最后自己从头训。公司两年前起步时的赌注是：RL 对齐聊天模型已被验证，把它用到数学和代码上就能做出 agentic 系统，而且可以资本效率更高地在开放模型底座上做研究。「然后第一年发生的是——所有好的开放模型都来自中国，西方几乎没有」，而他们需要一个底座；同时他们发现想在大规模上把 RL 做好，实际上必须自己预训练，两者耦合太紧。于是转向端到端自研。团队从一年前约 30 人扩到约 300 人，铺开预训练 / mid-training / RL 全部团队。
  • 追赶前沿的价码，按年翻倍。他的估算顺序感很清楚：大约 18 个月前是「数亿美元」量级，半年前是「单数字十亿美元」，明年是数百亿美元量级。他给的经验法则是每代模型大约 4 倍算力：10 万张 H100 → 10 万张 Blackwell（Astra 那次运行）→ 下一代会是约 10 万张 Vera Rubin。但他也认为这条曲线终将渐近——前沿实验室正在投数千亿美元，翻到万亿级「不太可能」，因为算力使用效率本身在快速提升。
  • 效率提升的数字很硬。他说纯靠人类研究员时，预训练侧的算力效率大约每年 7 倍，这是可以用预训练 loss 具体度量的东西；而现在系统里（尤其 RL 侧还有大量空间）大约是 30 倍，「大概比研究员单干快四倍或更多，而且还会加速」。他举了例子：现在「一周可以做完一个博士」——并顺带提到 OpenAI 最近几周证明的那批数学定理。
  • 开放权重的安全论证。开场就是他最强的论点：「当你移除网络攻击能力时，你也移除了网络防御能力」；今天全世界只有数百名闭源实验室里的安全研究者理解这些东西的运作方式，「无论他们意图多好，都不可能覆盖这些系统可能带来的长尾意外后果」。他给的经验证据是：一个非常强的闭源模型入侵了另一家公司，而那家公司唯一能自愈的方式就是用开放模型保护自己。随后是那句 Linus 定律的改写——「只要有足够多的眼睛，大多数安全与安全漏洞也会变得浅显」。他把互联网类比成白细胞生态：让更多人拥有防御能力，实际上是在帮你抵御攻击能力。
  • 地缘与商业。他认为中国某种程度上是「captive market」——可以在那个市场里做开放模型同时赚到很多钱；而下一阶段会看到华为这类公司提供全栈方案并锁定一个国家的供应链。他建议把 AI、芯片、数据中心当成铁路那样理解：根本性的基础设施，而大多数国家建不起自己的铁路，只能接入某一方，因此具有地缘杠杆。他的对照是软件与互联网——美国在所有这些有意义的通用技术上都让世界建立在它的东西之上。

把这一节与前六节放在一起，今天的叙事就完整了：Anthropic 说 agent 的安全边界必须靠架构；Vercel 说 agent 已经占了流量的大头；Reflection AI 说开放权重是唯一可能跟上攻防节奏的经济形态。三者在不同楼层讲同一栋楼。

八、行业信号：降价潮的成因、与「别再邮箱助手了」

  • @realmadhuguru（Meta AI 高级总监）（9 赞，但分析质量远高于热度）纠正了一个流行归因：开放权重模型并不是「单位智能价格」下跌的起点，它们只是已经进行中的趋势的顺风车。真正压低价格的三个因素一直是：① 模型厂商把最好的模型蒸馏进更小的模型，换来更便宜的推理；② 基础设施效率；③ 模型厂商之间的竞争。他的规律一句话可记：「第 x 代中杯模型的智力 = 第 x−1 代大杯模型的智力，同样的智力，更少的钱。」
  • @petergyang（237 赞）的一句吐槽被大量转发：「不如我们别再建更多管邮箱的个人助理，而是多建一些管理和治愈疾病的 AI 创业公司吧。」在 agent 供给过剩的一周里，这是关于注意力分配最直白的一句。
  • @nikunj（FPV Ventures）（35 赞）给创始人一条公关建议：如果要在 X 上推产品，请让你的市场团队把 VC 从投放名单里排除——他每天收到三条「合作一下这个天赐良机」的 DM，本质是付费合作；「这显示出很差的判断力，而消息会传开：你在试图买眼球来铺垫下一轮融资」。在一个 agent 可以自动投广告的月份，这条尤其值得存档。
