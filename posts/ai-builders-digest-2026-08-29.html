三、Anthropic 工程博客：Claude Code 质量下降复盘

Anthropic 发布工程博客《An update on recent Claude Code quality reports》，罕见地详细复盘了近期用户反馈"Claude 变笨了"的三个根因：

  • 根因一（3月4日）：将 Claude Code 默认 reasoning effort 从 high 改为 medium 以降低延迟，但用户反馈智能度下降，4月7日回滚。影响 Sonnet 4.6 和 Opus 4.6。
  • 根因二（3月26日）：为空闲超1小时的会话清除旧 thinking 以降低延迟，但 bug 导致每轮都清除，使 Claude 看起来健忘且重复。4月10日修复。影响 Sonnet 4.6 和 Opus 4.6。
  • 根因三（4月16日）：添加减少冗长的系统提示指令，与其他提示改动叠加后损害了编码质量，4月20日回滚。影响 Sonnet 4.6、Opus 4.6 和 Opus 4.7。

关键结论：API 和推理层从未受影响，三个问题分别影响不同流量切片，叠加后看起来像广泛的不一致退化。Anthropic 承诺加强内部 dogfooding、系统提示变更的 eval 覆盖、以及更渐进的灰度发布。阅读原文

四、Anthropic 工程博客：Scaling Managed Agents——脑手分离

第二篇 Anthropic 工程博客《Scaling Managed Agents: Decoupling the brain from the hands》探讨了如何设计长时序 Agent 系统：

  • 核心理念：借鉴操作系统的虚拟化思路，将 Agent 的三个组件抽象为可独立替换的接口——session（追加写入的事件日志）、harness（调用 Claude 并路由工具调用的循环）、sandbox（执行环境）。
  • 踩坑教训：最初把三者放进一个容器（"pet"模式），容器挂了 session 就丢了，调试还得进容器开 shell，而容器里又有用户数据——无法调试。
  • 解法：把"大脑"（Claude + harness）与"双手"（sandbox + tools）和"会话"（session log）解耦，每个都可以独立失败和替换。
  • 设计哲学：Managed Agents 是一个"meta-harness"，只对接口形状有主见，不对背后跑什么做假设——未来无论 Claude 需要什么样的 harness 都能适配。
