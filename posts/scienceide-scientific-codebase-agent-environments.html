ScienceIDE：把世界科学代码库变成 Agent 可学习环境

September 17, 2026

科学代码库沉淀了几十年的可执行人类知识——数值模拟器、物理求解器、生物信息流水线。但当你想让 AI agent 从这些代码里学东西时，会发现它们几乎无法直接转化为训练经验。ScienceIDE（arXiv 2609.19134，PhAI-Labs × Qwen 团队，2026-09-16）给这个问题起了名字：科学经验瓶颈，并给出了一条从「专家判断」到「无限任务」的完整流水线。

核心论点：把专家的科学验收标准固化成可执行合同，让工厂复用合同批量产任务，用执行证据而非 AI 自评来准入——一个环境同时服务评估、SFT 和 RL。

一、什么是科学经验瓶颈

代码智能能靠 RL 飞轮成长，靠的是 repo + 编译器 + 测试构成的可验证经验闭环。科学代码在这个闭环的每一环都断了：

  • 执行不可复现：工具链异构、依赖混乱、构建假设散落各处——科学 repo 先要能稳定跑起来才能当环境
  • 正确性标准隐式：验证依赖物理量、数值容差、不成文的领域约定。SWE-bench Science 已经发现：软件测试会欠指定科学合同
  • 跑通 ≠ 可学：还需要行为验证、分级反馈、记录交互，才能支持评估/SFT/RL

现有科学基准——SciCode（80 题）、ScienceAgentBench（102 题）、SWE-bench Science（119 题/98 repo）、CORE-Bench——都只做评估，不提供批量生产经验的工业基础设施。专家出题贵、会饱和、公开答案会污染。

二、方法：专家判断 → 可执行科学合同

构造单元是版本化代码库中一个科学模块（有连贯科学职责 + 可执行覆盖，不是文件分组）。流水线五步：

2.1 官方测试到科学检查（全文最核心的一节）

奖励单位是 check = 固定输入 + 分级输出 + pass policy。两种策略：

策略形式适用场景
Pointwise|c−r| ≤ a + ρ·|r| 逐值比较能装下测量敏感度、同时拒绝真实故障；精确相等是 a=ρ=0 特例
Invariants守恒量、矩、分布、积分范数逐值容差装不下 run-to-run 涨落：随机流、快发散流、采样统计、离散输出

校准证据链：名义/扰动双运行测数值敏感度（variant 扰动最小充分输入集）→ 可选 altbuild 跨构建交叉验证 → 自验证要求两者独立复现参考并拿满奖励 → 每条检查附自然语言 warrant（识别可观测量、说明容差区分哪种科学偏差、解释为何合法实现能满足）。

最关键的原则：只给物理可观测量打分，不给簿记打分。粒子属性跟随 particle ID 对齐而非数组槽位；存储顺序、自适应步数、耗时、rank 布局、随机数、特征向量相位都不是 observable。防 reward hacking 从校准层做起，而不是事后审计。

2.2 七类任务工厂

Acceleration / Repair / Discovery / Reproduction / Integration / Calibration / Implementation。机械操作（变异、切除）自动化，可观察量/等价性/验收永远在专家手里——「机械作者操作可复用，科学判断不随之下放」。

2.3 执行证据准入

注入型修复任务需要三重证据：已验证 witness 通过检查、未修复 baseline 留有 headroom、改动确实消除检查失败。静默突变保留为显式对照组。修复得分对 baseline 归一：

r_repair = max(0, (r − f) / (1 − f))

一个环境同时服务修复、实现、复现、加速——「同一环境，换任务不改合同」。

三、规模：27 代码库 → 64 环境 → 2,812 任务

  • 2,515 修复 + 295 实现 + 2 加速任务，1,076 条可执行检查
  • 覆盖 PLUTO、Athena++、MITgcm、LAPS、PHANTOM、Meep、pymatgen、QuTiP、Stim 等天体物理/等离子体/海洋大气/粒子/光学/材料/量子模拟代码库

三个值得记住的细节：

  • 预算耗尽占 task-balanced 失败的 37.3%——长程性是主要瓶颈，不是智力
  • 相似终分掩盖时间需求：10 分钟时 Astra 49.6% vs Fable 25.9%，Fable 到 ~31 分钟才反超；20→60 分钟区间 Astra 只 +2.0pp、Qwen3.8 Max +30.2pp

这是科学经验对通用能力正迁移的实证：只在科学代码修复轨迹上做 SFT，BBH 排序、GSM8K 数学、HumanEval 修复都跟着涨——Science4AI 假设有了第一批硬数据。

六、RL：一个所有做 agent RL 的人都该记住的失败模式

Qwen3.5-4B，LAPS（3D 伪谱 Hall-MHD 求解器）+ MITgcm-biogeo（海洋生物地球化学），outcome-only 奖励——verdict 要等 episode 结束、编译通过、真实模拟跑完才产生。

失败模式（未 mask 的 run 直接观察到）：

  1. episode 有三种结束方式：修复完成 / 轮次上限 / 预算耗尽——只有第一种说明修复成败，但 0 奖励对三者一视同仁
  2. token-mean 聚合下，截断轨迹的 0 奖励变成对其中每个 token 的惩罚——对最长轨迹惩罚最重
  3. 而最长轨迹往往在尝试最难的修复 → 政策学会把轨迹做短
  4. 每轮 token 掉 3 倍以上 → 更多截断 → 自增强循环，奖励崩到起点以下

修法三件套：截断轨迹保留在 group baseline 但从 loss mask 掉；关掉 DAPO 奖励侧长度惩罚（长度反映缺陷定位难度，不是该罚的量）；不对称 clip（ε_low 0.2 / ε_high 0.3）+ Dr.GRPO 去组标准差除法。

指标LAPSMITgcm-biogeo
held-out 奖励0.357 → 0.857（2.4×）0.286 → 0.571（2.0×）
截断率39.5% → 6.6%34.1% → 23.8%

截断率大降而响应变长 = 政策把「死在预算线上」的长尝试转成了拿到 verifier verdict 的完整 episode——学会的是解决任务，不是缩短轨迹。奖励信号直接来自编译 + 跑真实科学模拟的 verifier，不是学习到的代理模型。

七、诚实局限（作者自己列的）

  • 证据限于参考可验证的软件任务（计算物理/地科的修复与实现），不是开放式发现
  • 工厂变体共享代码路径——任务数 ≠ 独立科学覆盖
  • 容差内一致 ≠ 检查之外正确；独立外部审计与对抗 reward-hacking 评估还是欠账
  • SFT/RL 增益都没证明跨代码库迁移；RL 对比无 seed 间方差
  • 预训练可能见过公开源码：legacy 镜像保留时间戳线索，难度选择先于完整检索隔离

八、我的三点收获

1. 抽象升级：benchmark 实例 → 可复用环境单元。专家验收标准固化成 check + warrant 一次，工厂无限产任务。任何需要专家判断的领域（不只是科学）都可以套这个模式——关键洞察是「合同先于出题」：check 套件在任务生成之前固定，任务可以千变万化，验收合同不变。

2. 预算截断的 loss mask 是可以直接抄的工程细节。任何满足「episode 可能因预算结束 + 奖励只在结局产生 + loss 按 token 聚合」三个条件的 RL 系统都有同款陷阱。检查你的 trainer：截断样本是拿 0 奖励进了 loss，还是被正确 mask？

3. 评估 agent 要看时间-质量-成本三维曲线。成功率和 token 花费零相关意味着「烧更多 token」既不等于更努力也不等于更好——Astra 用 Fable 一半不到的钱、三分之一的 token、60% 的时间拿到了差 4 个点的分数。
