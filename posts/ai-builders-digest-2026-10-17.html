AI Builders 日报 · 2026-10-17

October 17, 2026

今天的 Builder 圈，两条主线：一是 OpenAI 把「模型自己加速模型」摆上台面——Sam Altman 晒出 Navier-Stokes 里程碑纪念衫，Box CEO Levie 长文论证递归自我改进（RSI）飞轮已经点火；二是 Anthropic 把能力落到产品——Claude Slides 与 Claude Code Review 在资深工程师圈子里刷屏。另有一期 No Priors：Greg Brockman 谈 AI 如何改变网络安全与药物研发的「物理」。

模型不仅能解题，还能解「训练下一个模型」这道题之后，飞轮就开始自转——算力、agent 基建与数据三股力量叠加，前沿天花板的上推速度大概率比过去更快。

一、模型前沿：Navier-Stokes 里程碑与递归自我改进

Sam Altman 晒出 Navier-Stokes 里程碑纪念衫：衬衫背面印的，正是这道题解法的链式思维（chain-of-thought）最后一行。这条 9023 赞的帖子没有更多解释，但配上同一天 No Priors 节目里被点名的话题——OpenAI 的数学成果与 Astra——基本坐实了团队近期在「AI 生成新知识」上的进展。

Amjad Masad（Replit）给数学圈的情绪变化来了个画像：数学家们正以极快的速度经历悲恸五阶段——否认、愤怒、讨价还价、沮丧、接受——「我们现在处在沮丧的尾声，正在走进接受」。651 赞、40 转。

真正值得逐句读的是 Aaron Levie 的长文。他的判断：我们已经到了一个临界点——AI 比人类更擅长训练模型这件事，正从「遥远」变成「就在眼前」。驱动这个飞轮的是四股力量：模型能力终于超过大多数人类工程师、长时运行 agent 的 harness 与基建在进步、数据供给持续扩大、以及 agent 可以并行拆解远超个人能力的任务与测试。他的结论很直接：「如果你还没有把 RSI（递归自我改进）的后果计入预期，那可能是个错误。」

二、Claude 生态：Slides 与 Code Review 刷屏

Anthropic 的 Boris Cherny 两条帖子这两天在工程圈刷屏。第一条关于 Claude Code Review：「我无法想象没有 Claude Code Review 还能高效工作。它跑在我所有 PR 上，几乎在每一个 bug 进主干之前就抓住它。」——3399 赞、105 转，是这轮传播的顶点。第二条给 Claude Slides 带货：「别再睡了，这就是我现在做 PPT 的方式，再也不用去搜 iphone frame svg 了。」（3025 赞）。

Claude 产品线负责人 Thibault Sottiaux 确认 Slides 支持昨天刚上线，先在 Pro / Business / Enterprise 灰度，边收集反馈边迭代（556 赞）。

官方号 @claudeai 则连发两条用例：Haiku 5.5 写了二十首俳句，再用 JavaScript 逐帧画出动画（644 赞）；一位心内科 fellow 用 Claude 搭了个 3D 工具，帮学员练习读冠状动脉造影（1506 赞、67 转）——后者是「专业人士用 AI 做垂直教学工具」的典型样本。

三、产品与工具：更快的 TypeScript，和「数据不出门」的 Replit

Guillermo Rauch（Vercel）玩了个梗：「TypeScript 是新的 TypeScript」——经过 scriptc 编译后，性能比 tsgo 快 2–4 倍（341 赞）。工具链的性能竞赛还在继续。

Amjad Masad 宣布 Replit 支持部署到客户自己的云：「数据永远不出门」，面向政府、金融、医疗这类高合规场景（144 赞）。

Garry Tan（YC）分享自己的新项目起步姿势：capydotai 配 AsideAI，让 agent 同时搞定第一版代码和 DevOps 搭建，一次到位（187 赞）。

四、观点：生成已足够便宜，下一步拼编辑与监督

Dan Shipper 一句话点破当下瓶颈：「生成已经又便宜又高质量；我们缺的那块能力，现在是编辑与监督（editing and oversight）。」——这和 Levie 的飞轮论互为印证：产出不是问题，谁在环里把关、怎么把关，才是下一步。

五、播客：Greg Brockman 谈安全与药物研发的「物理」

本期 No Priors 请到 OpenAI 联合创始人兼总裁 Greg Brockman（发布于 10 月 15 日）。话题横跨：OpenAI 最新的数学成果与 Astra、为什么 Greg 认为 AI 现在能生成真正的新知识、药物发现，以及一个相当大胆的论断——「当软件变得如此便宜，你想要的不是软件，而是可靠、安全、可信任的软件；安全支出最终应当远超软件支出。」

完整节目见 No Priors（YouTube）。
