开篇

今天 10 位 builders 的 X 时间线里（共 21 条），没有重磅模型发布，但有几条很值得咀嚼：Guillermo Rauch 用一个 WebGL2 物理仿真把黑胶唱片「拆」成了可播放的凹槽；Nan Yu 抛出一句工程箴言「选最笨的，而不是最简单的」；Aaron Levie 连发两条长帖，把 Agent 的价值描述成「生产力提升没有上限」。中间还夹着一场关于 「vibe coding」这个词该不该换掉 的争论。

核心信号：AI 的下一波不是「更强的模型」，而是「更敢做梦的产品 + 更克制的工程判断」——前者把物理世界也拖进可仿真、可重混的范畴，后者提醒你：简单是迭代出来的，笨才是对的起点。

一、产品与创意：把物理世界也「拆开重混」

  • Guillermo Rauch（Vercel CEO）：用 WebGL2 + Web Audio 做了一个黑胶唱片机的物理仿真（今日最高互动，2242 赞 / 143 转）。它不直接放歌，而是把歌曲转换成凹槽的物理形状，再由一根模拟唱针以每秒 384,000 次的频率「骑」在槽壁上，输出感应到的电压——于是爆音、炒豆声、抖晃、内圈发闷这些「缺陷」都成了仿真的自然副产品，你甚至可以「打碟」。代码已开源可重混。这篇 Demo 的意义在于：当仿真精确到物理层，媒介本身的「缺陷」就从 bug 变成了可调音色。原文
  • Garry Tan（YC CEO）：转发并断言「你真的会想要一座自己的软件工厂」——配合前沿模型改写代码的能力，这种诉求正在从口号变成刚需。原文。同主题他还补了一句：一旦意识到软件在前沿模型手里「这么好改」，那些陈年 bug 就开始变得难以忍受，而「个人即时软件（just-in-time software）」几乎是必然。原文

二、工程方法论：选「笨」的，不选「简单」的

  • Nan Yu（OpenAI Codex 产品，前 Linear 产品负责人）：力荐「挑最笨的方案，而不是最简单的」——简单是你迭代出来的结果，笨才是正确的起点，否则你会开始「聪明反被聪明误」。这条几乎适用于软件的所有方面：选能用的最笨架构、选能成事的最笨设计；「耍聪明」意味着你的用户也得一样聪明才看得懂你的聪明。（263 赞 / 11 转）原文
  • Nan Yu 另有一条同源判断：软件「在你清楚想构建什么时变得简单得多，在你不知道时难得多」——有清晰目标就能直冲解法，没有就会堆出一堆垃圾还烧钱；Pre-AI 时代你什么都交付不出来，现在能交付垃圾，也算一种进步。（193 赞 / 11 转）原文

三、Agent 规模化：生产力提升「没有上限」

  • Aaron Levie（Box CEO）：一条长帖给出他对 Agent 时代的核心判断——AI 正从「陪你一问一答」的节奏，切换到「设定一个问题、一群 agent 散开去做任意大规模的工作」。生产力提升从约 20–50% 的「线性」区间，进入「没有上限」的区间。他点名了几个将被重塑的领域：编码已见分晓，接下来是网络安全（更多 agent 审查更多东西→更好结果）、生命科学，以及一切能并行化的知识工作。关键一句：「我们的大脑还没适应『计算成为可以随意拉满、用来解任何问题的变量』这个新设定。」（256 赞 / 18 转）原文
  • Aaron Levie 另一条则是给 AI 从业者的实用忠告：每 3–6 个月要回头重试一次以前做不到的事——过去半年里 computer use、上下文退化、推理、多模态、领域专长的进步，让这些模型「能执行的东西」大幅变强。结论：任何有 API（甚至很多没有）的东西，都可能被 agent 接管作为底层能力，于是安全、IT、数据、架构设计等各行业的 agent 都能挂到现有工具之上。（278 赞 / 19 转）原文

四、行业与术语：「vibe coding」这个名字要不要换？

  • Zara Zhang：几乎不再用「vibe coding」这个词——它隐含「你没投入多少心力、产出只是 AI 垃圾」的贬义，但现实里很多人用 AI 编码工具时明明倾注了心血，两者并不矛盾。她呼吁给这种「借 AI 之手、倾注灵魂的构建」找一个更好的词。（404 赞 / 182 回复，今日讨论度最高的术语之争）原文
  • Zara Zhang：产品的乐趣，来自「技术行为可预测」与「人类行为不可预测」两者的碰撞。（168 赞 / 7 转）原文
